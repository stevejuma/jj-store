# M8a LocalTrusted release acceptance

The first application release is one local topology:

- macOS ARM64 with Rust 1.98.1;
- configuration format 2 generated by `jj-store init --local`;
- literal-loopback HTTP and an owner-only Unix RPC socket;
- the pinned embedded RustFS 1.0.0 helper and an explicit persistent volume;
- no user authentication or external object-store service.

`pnpm test:local-release` cold-builds the browser, native binaries and embedded
helper, creates and registers a native repository, and exercises the built
browser. Acceptance covers token-free bootstrap and auto-open, external CLI
publication, SSE freshness with explicit refresh, atomic conflict resolution and
a typed browser mutation. The fixture verifies format/access/storage metadata,
keeps credential-shaped fields out of runtime metadata, and requires both cold
and restart startup below 30 seconds with combined server plus RustFS RSS below
512 MiB.

The 28 September 2026 macOS ARM64 cold run started an empty-volume server in
10,790 ms, restarted the populated installation in 408 ms, and measured 142,896
KiB combined RSS for the server and embedded RustFS processes. All four built
browser scenarios passed in 21.2 seconds.

The managed-storage acceptance separately covers exact object persistence after
graceful and abrupt shutdown, exclusive ownership, missing volume and identity,
private credential permissions, occupied storage ports, missing buckets and
sentinels. The LocalTrusted executable acceptance covers the mode-0600 Unix
socket, token-free native creation, protected loopback HTTP, catalog
persistence, live `doctor` diagnostics and restart.

The release does not qualify authenticated/shared serving, external S3,
background search indexing, backup or restore, RustFS replication, MinIO/AWS,
Linux/Windows packaging, authority migration, failover, promotion, Git, Nostr,
Smart HTTP, registry publication or visual baselines.

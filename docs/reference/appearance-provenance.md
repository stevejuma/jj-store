# Appearance source provenance

The device Appearance page adapts Buzz desktop source at
`ef2aa1ae38fadcc0bc22b8bf6ed96b35933146be` (Apache-2.0):

- `desktop/src/features/settings/ui/SettingsPanels.tsx` supplies theme ordering,
  gallery and section composition.
- `desktop/src/features/settings/ui/AppearanceSettingsControls.tsx` supplies all
  controls and preview composition.
- `desktop/src/features/settings/ui/SettingsOptionGroup.tsx` supplies group and
  row geometry.
- `desktop/src/shared/theme/ThemePreviewFrame.tsx` supplies theme preview
  geometry.
- `desktop/src/shared/theme/theme-loader.ts` supplies the 62 names, 19 light
  themes and reciprocal pairings.
- `desktop/src/shared/theme/adaptive-theme.ts` supplies the palette derivation
  copied into `web/src/lib/appearance/adaptive-theme.ts`.

App-owned implementation lives in `web/src/lib/appearance` and
`web/src/lib/ui/store-appearance`. Branding, scope and native transport remain
jj-store-owned. Secondary text is adjusted to preserve at least 5.5:1 contrast
on derived background, muted, chrome and popover surfaces. Browser glass reveals
the application background. Links use existing URL/text only and never fetch
metadata or images. Preview illustrations use local CSS and inline SVG under the
unchanged strict CSP.

Shiki theme data is bundled from `@shikijs/themes` 4.0.2 (MIT; Pine Wu and
Anthony Fu). `scripts/appearance-palettes.mts` generates one stylesheet per
palette and its import index; `--check` verifies generated bytes. Inter Variable
comes from `@fontsource-variable/inter` 5.2.8 (SIL Open Font License 1.1),
scoped to the Appearance page. Redistributed license texts are under
`docs/licenses`.

Design Core's inherited `--ui-ai-chat-type-scale` and native Scroll Area host
extensions are developed in the separate `design-core-jj-store-appearance`
workspace. Consumer acceptance uses an explicit temporary pnpm hook at
`/tmp/jj-appearance-pnpm.cjs` with
`npm_config_pnpmfile=/tmp/jj-appearance-pnpm.cjs pnpm install --no-frozen-lockfile --lockfile=false`.
Publishable package and lockfile ranges remain registry-based. A foundation
release and registry-only qualification are separate gates; this validation
setup is not publication evidence.

Local main landing is recorded in E-UI-053. The default Design Core workspace
contains `yovkqwtu`; jj-store main uses its existing ignored `.pnpmfile.cjs`
source hook with `pnpm install --no-frozen-lockfile --lockfile=false`. Installed
foundation files match the landed source. Main retains portable registry
manifests and lockfiles. The published 0.2.0 tarball lacks these extensions, so
this local main acceptance is not registry-only release qualification.

The Original picker option preserves the pre-Appearance app palette. Before
`rmwvnkzr`, `web/src/style.css` imported Design Core's default `styles.css`
without the named Lapis theme. `palettes/original.css` snapshots its public
semantic colours from released Design Core 0.2.0 `src/theme.css`; the release
tarball and currently installed source contain identical default theme bytes.
The two variants pair in System mode. Original uses the foundation's native
accent, while retaining the saved accent choice for other palettes. Buzz's 62
generated styles remain separate from this historical snapshot.

The token alignment audit in E-UI-055 compares those defaults with the new
GitHub Light Default palette and Buzz's component bindings:

| Role or surface           | Previous light theme                                          | Buzz-derived GitHub Light Default                                | App binding                                                  |
| ------------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------ |
| App background            | `oklch(100% 0 0)` (white)                                     | `#fff`                                                           | `--background`                                               |
| Popover background        | `oklch(100% 0 0)` (white)                                     | `#ebebeb`                                                        | Menus retain `--popover`                                     |
| Main text                 | `oklch(15% 0.05 295)`                                         | `#1f2328`                                                        | Values, headings and actions use `--foreground`              |
| Secondary text            | `oklch(50% 0.05 295)`                                         | `hsl(212 7.94% 37.1%)`                                           | Helpers and placeholders use `--muted-foreground`            |
| Composer                  | Foundation composer uses `--popover`; editor has its own fill | Buzz uses `bg-background`, `border-border/50`, no resting shadow | App background and transparent Mira editor                   |
| Normal/confirmation modal | Foundation dialog tokens use `--popover`                      | Buzz uses `bg-background`                                        | Public dialog background/foreground tokens bind to app roles |

Buzz reference paths are `desktop/src/features/messages/ui/MessageComposer.tsx`,
`ComposerAddressControls.tsx`, `MessageComposerToolbar.tsx`, and
`desktop/src/shared/ui/{dialog,alert-dialog}.tsx` at the same pinned revision.
The composer passes the existing foundation send-button part to preserve its
circular geometry. The Mira bridge captures palette roles on the composer
ancestor before Mira defines reverse aliases. Standalone file/code editor
surfaces and palette generation remain independent of these app bindings.

The app shell paints the Buzz gradient once across its viewport. Header and
left-navigation chrome reveal the same image, with glass opacity/blur applied
above it when enabled. Compact navigation section pickers bind public Popover
and Command View background tokens to the app background, following the user's
requested white light-Buzz surface; the generated popover palette and other
menus retain their existing roles. These are app-owned presentation adaptations.

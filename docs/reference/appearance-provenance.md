# Appearance source provenance

The device Appearance page adapts Buzz desktop source at
`ef2aa1ae38fadcc0bc22b8bf6ed96b35933146be` (Apache-2.0):

- `desktop/src/features/settings/ui/SettingsPanels.tsx` supplies theme ordering,
  gallery and section composition.
- `desktop/src/features/settings/ui/AppearanceSettingsControls.tsx` supplies all
  controls and preview composition.
- `desktop/src/features/settings/ui/SettingsOptionGroup.tsx` supplies group and
  row geometry.
- `desktop/src/shared/theme/ThemePreviewFrame.tsx` supplies theme preview
  geometry.
- `desktop/src/shared/theme/theme-loader.ts` supplies the 62 names, 19 light
  themes and reciprocal pairings.
- `desktop/src/shared/theme/adaptive-theme.ts` supplies the palette derivation
  copied into `web/src/lib/appearance/adaptive-theme.ts`.

App-owned implementation lives in `web/src/lib/appearance` and
`web/src/lib/ui/store-appearance`. Branding, scope and native transport remain
jj-store-owned. Secondary text is adjusted to preserve at least 5.5:1 contrast
on derived background, muted, chrome and popover surfaces. Browser glass reveals
the application background. Links use existing URL/text only and never fetch
metadata or images. Preview illustrations use local CSS and inline SVG under the
unchanged strict CSP.

Shiki theme data is bundled from `@shikijs/themes` 4.0.2 (MIT; Pine Wu and
Anthony Fu). `scripts/appearance-palettes.mts` generates one stylesheet per
palette and its import index; `--check` verifies generated bytes. Inter Variable
comes from `@fontsource-variable/inter` 5.2.8 (SIL Open Font License 1.1),
scoped to the Appearance page. Redistributed license texts are under
`docs/licenses`.

Design Core's inherited `--ui-ai-chat-type-scale` and native Scroll Area host
extensions are developed in the separate `design-core-jj-store-appearance`
workspace. Consumer acceptance uses an explicit temporary pnpm hook at
`/tmp/jj-appearance-pnpm.cjs` with
`npm_config_pnpmfile=/tmp/jj-appearance-pnpm.cjs pnpm install --no-frozen-lockfile --lockfile=false`.
Publishable package and lockfile ranges remain registry-based. A foundation
release and registry-only qualification are separate gates; this validation
setup is not publication evidence.

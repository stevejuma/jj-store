# Desktop governance

Desktop host source, its independent lockfile and packaging configuration are
protected by desktop.md. The same slice records launch-interface changes in
cli.md and package-boundary changes in architecture.md. Desktop qualification
keeps process, real-RustFS, browser and actual WKWebView evidence distinct.

Integrated desktop chrome remains an owned presentation adaptation. Extracting
already-global Community header hover styles into an owned CSS file preserves
their selectors and records the original Community source and license in
ui-provenance.json. Native titlebar configuration and narrowly scoped window
permissions live in the host; the renderer's versioned marker remains a
presentation hint and cannot authorize repository operations.

Buzz-derived native glass and header geometry retain source revision and
Apache-2.0 attribution separately from Community copies. Glass qualification
checks serialized native installation acknowledgements, opaque failure fallback
and cold saved-preference restoration. AppKit interop is limited to documented
main-thread retained-window and notification borrows in the native chrome
module; its one observer has explicit exit cleanup and no stored platform
pointer. The remaining host denies unsafe code. Native hover and alignment
acceptance includes active window movement and resize observations, with manual
evidence retained when macOS screen-sharing UI obscures the traffic lights.
Focused browser and host checks do not qualify visual baselines or public
distribution.

The tracked application-feedback guidance prefers scoped Design Core toasts for
transient operational feedback. JST-UI-019 owns lifecycle, accessibility and
contextual exceptions; notification changes retain focused UI and cold browser
evidence without rerunning unrelated Rust/storage qualification. Pending shared
package release and registry-only acceptance remain distinct from local source
validation.

Common-native identity-join changes qualify the complete direct AgentStore WAL
catalog binary, native/local service capture and binding/paging consumers, and
CLI spool/publication/recovery contracts. Named duplicate-identity and
concurrent cross-profile regressions precede those broader focused binaries.
Bounded alias lookup uses a separate incomplete-proof regression. Native
MemoryStore recovery and real Git companion reopen remain separate evidence;
neither qualifies a real harness edit, RustFS or automatic worker composition.
Partial qualification may add evidence to a Planned verification row without
claiming the complete requirement is implemented.

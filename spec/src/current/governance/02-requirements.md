# Requirements

| ID          | Requirement                                                                                                                                                                                                                                                                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| JST-GOV-001 | The canonical specification MUST live under spec/src, build with mdBook, and assign unique JST requirement IDs with exactly one verification row each.                                                                                                                                                                                                                    |
| JST-GOV-002 | Protected implementation, interface, tooling and guidance changes MUST update mapped owning topics or provide fresh justified unchanged-contract confirmation in the same Jujutsu change.                                                                                                                                                                                 |
| JST-GOV-003 | Every implementation slice MUST update the logical Progress ledger with actual commands, results, failures, affected files, versions/formats, gaps, next action and explicit milestone review in the same change.                                                                                                                                                         |
| JST-GOV-004 | Progress checks MUST validate task/dependency references, evidence links/test names, completion gates, and same-change ledger updates; passing bookkeeping MUST NOT substitute for passing product tests. Append-only metadata corrections MUST retain exact original payloads and outcomes, undergo strict replacement validation, and MUST NOT promote milestone gates. |
| JST-GOV-005 | Verified slices MUST be committed with Jujutsu while unrelated work and local workspace configuration remain uncommitted.                                                                                                                                                                                                                                                 |
| JST-GOV-006 | Rust formatting MUST use the pinned toolchain component and tracked rustfmt.toml, and MUST be checked by both normal and specification checks.                                                                                                                                                                                                                            |
| JST-GOV-007 | Verification MUST remain within the changed layer and direct consumers by default; full suites require independent cross-layer or multi-consumer impact, shared infrastructure, release qualification, or an explicit user request, with the escalation reason recorded.                                                                                                  |
| JST-GOV-008 | Community-derived presentation MUST be copied and maintained in this repository with complete source and license provenance; the ui-ownership plugin MUST reject runtime, build, test and type dependencies, external checkout links, substitutions and missing declared provenance.                                                                                      |
| JST-GOV-009 | Local UI development MUST support source-serving HMR with an existing compiled loopback backend, unchanged API admission and preserved native fixture; owned stop, backend-only restart and full-stack rebuild/restart MUST remain available.                                                                                                                             |
| JST-GOV-010 | Authored spec Markdown MUST remain within 400 physical lines and 32,768 UTF-8 bytes, with complete requirement, verification, navigation and lossless historical coverage.                                                                                                                                                                                                |
| JST-GOV-011 | Protected changes MUST record fresh owner coverage and milestone review, with explicit justified unchanged-contract confirmations permitted and original completion gates retained.                                                                                                                                                                                       |

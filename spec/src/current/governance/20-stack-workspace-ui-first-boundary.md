# Stack workspace UI-first boundary

The local stack workspace slice is governed by JST-UI-020. Changeyard is an
explicitly authorized composition and source reference; adapted source records
its original paths, revision and available attribution in UI provenance.
Existing owned Community and released Design Core primitives take precedence
when equivalent functionality exists. Production controller code cannot depend
on catalog fixtures. This slice runs focused controller and affected Storybook
interaction/accessibility checks, web/catalog type checks, ownership,
architecture and document/progress checks. Rust, checkout integration, public
transport generation and visual baselines are outside this slice. The user
approved backend implementation on 5 October 2026. Each backend slice
additionally runs the affected provider, service, transport and generated
contract checks; lifecycle and checkout slices require cold recovery evidence.

The registered working-tree observation route extends shared local binding
construction and HTTP state ownership. Its transport slice runs the complete
HTTP library lane, focused service observation/summary regressions, the existing
cold filesystem-only registration fixture, generated contract comparison and
complete registered-response validation. This escalation is for the shared
HTTP/contract impact; it does not require unrelated UI stories or Rust storage
suites. Cold observations prove unchanged code/companion/physical state and
remain distinct from command or active-combination acceptance.

Follow-up header drops and positional sorting retain exact branch and commit
identities in frontend mock commands. Extracted placement validation and drag
styles remain locally maintained with their source attribution. Geometry and
native hover evidence cover inline file alignment, selection markers, wrapping
chips, balanced stack/diff content padding before edge-aligned scrollbars,
aligned menu controls and Settings-style command forms. Only the Branches picker
retains its existing insets; stack and diff columns use the spacing on either
tab. Stack metadata omits the redundant Applied/Base row while keeping conflict
status in the header. Hover evidence includes light and dark modes. Native
pointer scenarios restore a neutral pointer position so adjacent stories retain
their own hover state; assertions remain unchanged. These refinements do not
open the backend approval gate.

Branch presentation additionally reuses the repository header row for the
workspace target above the tabs, opt-in Command View grouping for applied/local
branches, and owned Card/Button membership actions inside the selected stack
body. Footer values and the retained-draft action share the existing muted chip
surface. The commit title remains the public Input in a separated row, with the
public application composer below it. These refinements require their exact
interaction, theme, geometry and accessibility scenarios without screenshot
comparison or checkout execution.

The stacks integration retains main's M20 automatic-refresh milestone. Stacks
uses M21; historical E-M20-* evidence retains its IDs and original task fields.
The existing ledger family mapping resolves those fields only for task lookup,
so stacks evidence cannot qualify automatic refresh. Both parent histories
remain payload-identical.

The first approved stacks protocol slice adds owned service contracts and
focused identity, selection, apply and receipt regressions. Contract validation
does not qualify execution or persistence and adds no HTTP route. Required
checks are the affected service test binary and package checks, source
boundaries and mapped specification/progress gates. Generated transport checks
become required with executable route registration. Historical M21 stacks
evidence retains the E-M20-* family through the existing explicit task mapping.

Production Stacks browsing qualifies controller/adapter cancellation and
refresh, the affected application and repository Storybook consumers, and a cold
built browser against a disposable registered local folder. The read acceptance
checks operation heads, bookmarks, companion selection and physical files
before/after, and rejects unintended ordinary Log graph or command requests.
Fixture admission retains existing same-origin protocol headers. No Rust or
generated transport contracts change in this UI-only slice; physical scans and
durable commands require their own owning-layer and recovery gates. Historical
evidence payloads remain byte-identical and the ledger itself is never
reformatted.

The physical-read client slice runs exact transport/owner regressions and
directly affected Stacks, local-browser source and production application tests.
Lifecycle ownership requires fresh affected Storybook runs and a cold built
browser against a dirty disposable registered folder. The browser verifies
actual observation requests, exact dirty-path summaries, ignored obstacles,
retained historical selections/diffs and unchanged code/companion/checkout
metadata and files. No Rust execution changes occur in this client slice;
durable command/recovery gates remain separate. Historical ledger objects are
appended to without formatting.

Focused Stacks navigation reuses the existing repository history readers and
body tabs. Its acceptance covers route round-trips, retained controller/draft/
diff state, capability-gated entry, focused details and native hover/overflow.
The disposable Stacks browser runner accepts Playwright filters so navigation
and mutating megamerge acceptance can each start with a fresh folder, server and
graph index. Preparing history in one scenario must not substitute for a cold
command scenario. Existing live development services stay running. This frontend
slice changes no local JJ command or TOML contract and requires no Rust rebuild,
package publication or screenshot baseline update.

The ordinary local Stacks mutation acceptance uses the existing isolated cold
filesystem server and explicitly built development executables. It covers
selected-file staging, native lazy-hunk dragging, adjacent diffs and repository
Undo/Redo, including a CLI operation, while measuring retained merge/WIP change
identities and unchanged TOML. Graph-index preparation remains explicit after a
new operation. The runner cleans up its own service/folder and preserves the
live fixture. Interaction and accessibility evidence does not qualify visual
baselines or the historical manifest-backed prepared-command profile.

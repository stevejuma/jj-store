# Verification scope

Help presentation bundling consumes the existing application palette sources and
released local fonts. Changes to its asset generation and theme lifecycle run
the documentation-tool regressions and complete cold Help browser lane,
including embedded inheritance and standalone behavior. No repository storage or
Rust contract changes are implied by these presentation assets.

Installation capture management adds a server-package response capture to the
shared contract runner. Fixture selection binds package and test binary
explicitly; existing CLI captures retain their defaults. Changes to this runner
require every registered HTTP/SSE capture and contract-tool test, plus the
direct generated-client check. Authenticated control selection/application also
requires the complete owning server library and direct runtime/journal consumers
because foreground binding and journal coordination are shared. UI interaction,
real storage and live harness acceptance remain separate gates.

Capture runtime extraction qualifies the shared spool, sanitizer, native/local
drainers, lease recovery and their CLI/server consumers. Boundary checks reject
upstream JJ and CLI/server dependencies in jj-store-capture and reject runtime
dependencies in models, object storage and WAL. Existing public CLI capture
paths remain reexports; extraction does not qualify automatic discovery or
readers.

A logical behavior remains one verification surface when it spans its production
module, colocated styles, direct tests or stories, canonical chapter and ledger.
The number of edited files or stories does not trigger aggregate gates. UI-only
work runs the relevant web or catalog check plus the exact interaction,
accessibility or browser acceptance for that surface. Rust-only work runs the
affected package or crate checks and exact regression without unrelated UI or
workspace lanes.

Escalation to a full relevant suite requires impact across independent product
layers, packages, deployable surfaces or consumers, or a change to shared build,
test or runtime infrastructure capable of altering unrelated lanes. Release
qualification and an explicit user request also authorize escalation. Evidence
records the concrete reason before the wider command runs. Root aggregate
`pnpm spec:check`, `pnpm check`, `pnpm test` and `pnpm build` commands are not
default completion gates for a single-surface change.

Governance commands that read tracked specification state through child
processes use an explicit bounded output allowance large enough for the current
ledger. Growth beyond that allowance fails closed instead of truncating parent
evidence used by same-change validation.

Progress validation enumerates every direct parent of a JJ merge, audits the
union of changed paths and retains every parent's evidence signatures. Merely
combining existing entries does not satisfy the same-change integration gate;
the merge must add or update evidence absent from every parent. The published
spec-first CLI accepts explicit common-ancestor and merge commit IDs through
`--base` and `--head` for Git merge qualification; its default JJ `@-` selection
is single-parent only. The installed 0.1.0 CLI uses Git for explicit revision
arguments. JJ workspace stack qualification therefore enumerates the actual
`jj diff` paths and passes all of them through the supported `--file` interface,
alongside the default JJ gate for the integration change.

Bounded-read integration rebases the completed slices onto committed main while
preserving its repository conversion, terminal, capture settings and bundled
Help surfaces. Integration verifies the combined native/local routes and
generated contracts, native and local reader consumers, and
files/reference/preparation controller lifetimes. The ledger retains every
bounded-read evidence object and main entry; renamed historical test references
follow their owning test changes. Landing completed slices does not qualify the
remaining large-scale preparation, endpoint audit, collaboration/card
projections or fault/RustFS gates. Both main and the retained follow-up
workspace start from the verified integrated tip.

Landing the M13 workspace preserves native Projects browsing and development
fixture evidence alongside the local companion evidence. Integration resolves
shared paging visibility for both providers without changing native publication
or local ref authority. Tracked agent scope and `local-jj.md` must distinguish
implemented server-free WorkStore, agent provenance and repository-wide review
persistence from pending portable review anchors/CLI, filesystem serving/UI,
recoverable code mutations, conversion and cold full-flow gates. These pending
capabilities do not become qualified merely because their workspace is landed;
`milestones.md` remains the sole implementation status ledger.

The M0 contract harness is validated in both normal tests and spec checks. Real
storage qualification remains an explicit lane and cannot be inferred from the
harness self-tests or a source audit.

M9 owns the LocalTrusted AgentStore and ReviewStore delivery. Its publication
foundation is governed by `publication.md`; new domain crates and capture,
anchor, review or collaboration behavior are governed by `collaboration.md`.
Browser diff-line and agent-tool review creation, exact anchor resolution, route
retention and inline presentation are jointly governed by `collaboration.md` and
`api.md`. This includes byte-offset to line-coordinate presentation and the
exact CSP allowance required by the pinned Community emoji dependency. Each
separately registered captured-response fixture in `scripts/contracts.mjs` must
be recorded here and in the owning milestone's evidence ledger so generation
cannot widen runtime acceptance without same-change governance review. Upstream
Community and Design Core changes remain separate source-owned changes with
consumer acceptance in this repository.

Whole-session agent comments extend the native V1 review anchor surface and are
jointly governed by `collaboration.md`, `publication.md`, `compatibility.md`,
`api.md` and `cli.md`; their browser layout and reply presentation are governed
by `ui.md` and `projects.md`. Qualification includes canonical anchor/dependency
tests, receipt replay and snapshot-identity rejection after cold WAL reopen, the
existing admitted LocalTrusted HTTP review fixture and regenerated contract
conformance. Fake-memory recovery evidence is distinct from real-RustFS
qualification. Focused controller and cold Storybook consumers cover retained
drafts, unknown outcomes, independent tool/comment hover actions, thread reply
indentation, footer placement and Focus/Split layouts. Read-only live UI
inspection and interaction/accessibility passes do not approve visual baselines
or qualify the unsupported filesystem-local agent review profile. The milestone
ledger records these limits and the exact commands.

Repository-owned sidebar thread navigation is jointly governed by `ui.md` and
`api.md`. It reuses existing bounded authorized Threads reads, without altering
publication or persisted formats. Its evidence covers repository ownership,
permission/credential teardown, pagination, stale connections, indented
children, the Browse threads action and contextual breadcrumbs across desktop,
mobile and compact navigation. Interaction and accessibility evidence remain
separate from visual baseline approval.

request inspection, completion, paused replay after transcript removal, stopped
tail, strict input, changed reuse, revocation and disabled responses. The
complete registered HTTP/SSE inventory and generated-contract/TypeScript checks
remain required for this additive public contract. Native MemoryStore and
synthetic harness evidence do not qualify real harness/RustFS release or enabled
startup.

The M18.2 rescan fixture

The M18.2 harness coverage fixture

The M18.2 fixture
`sources::source_pages_are_bounded_cached_and_hold_no_admission_proofs`

checks physical slot retirement and source-state non-admission. Adding this

M10 owns local-first writable replication. Its origin ledger and imported
publication path are jointly governed by `replication.md` and the existing
publication requirements. Native head integration is also governed by
`jj-integration.md`; agent and review fact reducers remain governed by
`collaboration.md`. Backup and passive promotion retain their independent
adapter requirements.

Tracked agent guidance and CLI activation documentation describe the implemented
single-upstream profile as active while keeping its expanded qualification and
stock-JJ filesystem mirroring explicitly deferred. Scope alignment updates must
preserve that boundary in this chapter and in the milestone ledger.

The checkout-owned development harness stores its interactive fixture only in
the ignored `.local/dev-demo` subtree. Restart and stop preserve that fixture;
reset is the explicit destructive reseed boundary. Reset publishes
representative Codex, Cursor and OpenCode activity through the production hook
path, then creates repository, operation, revision, code-text, code-artifact,
agent-text and agent-artifact review anchors through the production ReviewStore
command route. Cold browser acceptance must provide a separate temporary root so
its publications and cleanup cannot alter interactive state. Harness state and
process markers remain separate so a stop cannot leave a stale PID that blocks
the next restart. When inline anchored review patches coexist with a primary
changed-file disclosure, browser acceptance MUST select the primary disclosure
explicitly. The loopback-only harness may recognize an exact validated Gravatar
request only to abort it locally; it MUST NOT permit an external response or
widen general network access.

The interactive demo enables the explicit loopback LocalTrusted browser
annotation policy. Generic cold browser acceptance opts out by default; the
exact annotation-policy browser gate explicitly opts in and proves that inline
helpers render. Strict asset and deployment rejection regressions remain
separate. API security policy and repository access guards are unchanged.

UI development additionally provides a Vite HMR mode that reuses an existing
complete fixture and executable without invoking UI, Rust or RustFS builds or
seed commands. Missing prerequisites fail before stopping a running service.
Runtime markers identify both owned processes; stop and full-stack restart
validate their ownership before signaling either. Backend-only restart retains
Vite. The existing full-stack rebuild/restart and explicit reset remain
available. Cold development acceptance covers real API admission, streaming,
HMR, backend restart and state preservation; built-bundle CSP qualification is
retained separately. No development workflow publishes a package or replaces the
installed CLI.

Development startup supplies the bundled `desktop/resources/jj-acp` and the
custom `jj` paired with the selected backend by default. The full restart builds
its development binaries before preflight so clean checkouts remain supported.
Full, HMR and backend-only restarts resolve these resources on every invocation,
preserving explicit trusted environment overrides. Preflight rejects missing,
non-regular, non-executable or pre-version-3 ACP resources before stopping an
existing service. This inspection never launches an adapter or sends a prompt.
The shared launcher regression includes a cold API capability/status check
before and after backend-only and full restarts, without inherited ACP
configuration.

The HMR preflight also validates the generated Help bundle before replacing a
process. Missing or invalid Help fails with `pnpm docs:build` guidance. Vite
reloads Help on manifest publication events, preserving the last validated
assets during rebuilds and releasing its observers at shutdown. This applies
without a Rust or UI rebuild, API polling, or an application document reload.

The same fresh fixture includes native WorkStore samples through its authorized
HTTP commands. The additive `dev:seed:work` command checks the matching owned
runtime before publishing, uses repository-scoped stable entity identities,
preserves existing edits and tombstones, and stops on an unknown command
outcome. Focused seed regressions cover interruption and idempotence. Cold
native browser acceptance proves the samples survive fixture preparation's
physical restart; all direct native-browser fixture consumers are requalified
when this shared seed changes. Interactive sample addition never invokes
destructive reset.

# Architecture

Main/Stacks workspace integration preserves both source histories and all
historical evidence. The native cache keeps bounded resident weights and
request-scoped loader ownership; the archived recovery reader builds topology
without preparing text filters. Focused native query, local workspace,
registered HTTP and browser checks qualify the combined tree.

Managed core code indexes consume owned native/local read sources through one
service owner. Standard JJ construction remains in `jj-store-jj`. Existing HTTP
repository monitors supply authoritative code-change episodes and existing
freshness producers publish readiness. Persistent derived cache reservations
share ordinary query disk quotas; immutable ready readers share process memory
retention. No index becomes repository authority and no user source is repaired.
Observation pressure (Busy, deadline or resource admission) MUST retain the last
repository witness and retry through the existing monitor. It MUST NOT announce
a repository as unavailable or trigger a read/refresh feedback loop. Confirmed
access or source failures retain their unavailable/invalidation path.

Integrated cold acceptance retains registration generation and exact operation
selections, compares source metadata bytes, verifies derived segment reuse
across restart and observes idle data requests separately from construction
scale, built-bundle release and fault qualification.

The browser's shared preparation owner composes graph and native kind tasks
through their typed data sources. Only the native profile supports kind starts;
local graph preparation remains unchanged. One active task retains original
operation/kind and bounded reports, observes settlement hints and cancels stale
HTTP reads. Kind status backoff supplies progress without event flooding or
parallel requests. Presentation uses the existing Settings command rows and
released Design Core Buttons, with no Community checkout dependency.

Remote native copy-family requests compose the existing checked-root service
provider through an owned transport facade and additive protobuf method. The RPC
crate retains no upstream JJ dependency or credential-bearing cache. Server
limits bound request conversion, shared construction and complete response;
client deadlines and strict decoders protect the remote factory consumer.
Acknowledged staging stays with the backend's captured local relations. App
recovery integration and complete scale/RustFS qualification remain open.

Native inventory pages scan one checked immutable catalog selection under
descriptor, record-read, encoded-byte, concurrency and deadline bounds. Process

they neither rebuild an inventory nor replace a retained root after publication.
Complete RPC enumeration retains only its bounded matching IDs. Authoritative
catalog, WAL and object formats remain unchanged; full closure audits remain
publication/recovery responsibilities.

The in-process native factories and legacy Inventory RPC share bounded complete

and immutable selection data under source scope, fixed expiry and shared

and time remain independently bounded; semantic publication continues to use the

Compact native/local ReviewStore activity is a read-only service projection of
the admitted first catalog window. It returns counts and maximum accepted times,
without anchor/comment presentation or causal event ordering. Provider closure

retain only count, incomplete flag and maximum time. Fresh provider admission
precedes reuse and snapshot envelopes stay request-owned. Cold loads coalesce
outside the map lock, canceled or failed loads admit no value, and active-slot
pressure falls back to request-local derivation.

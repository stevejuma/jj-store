# Native remotes source qualification

JST-DOC-002 requires original remote embedding guidance to distinguish the
explicit native writer from immutable readers and independent vault backup.
Source evidence does not qualify either cold application host or delivery.

E-ORIGINAL-REMOTE-001 proves guarded save, native tracking fetch and one
reviewed branch publication. E-ORIGINAL-REMOTE-002 adds real TLS smart HTTP with
temporary trust confined to the disposable Linux worker; ordinary certificate
and redirect verification remain intact.

E-ORIGINAL-REMOTE-003 documents operation-pinned native graph counts for a known
empty remote and an immutable reviewed commit. Missing local history remains
unknown; a later capture cannot alter the review's proposed commit or counts.
The native root is excluded from empty-branch outgoing counts. Documentation
retains the shared read budget and separate host/credential-custody gates.

E-FORGE-CUSTODY-FEATURE-001 documents default OS custody and the opt-out for
hosts injecting encrypted secret storage. The embedding guide names both Cargo
default selections and the fail-closed native-store behavior. Dependency-graph
and source tests qualify linkage selection only; Server image and both cold
applications remain separate acceptance gates.

E-ORIGINAL-REMOTE-004 separates passive native original inspection from writer
admission. The embedding manual names the immutable constructor and retains
explicit write admission for save, fetch and publication. Read-only source
qualification does not enable host routes or complete application acceptance.

E-ORIGINAL-REMOTE-005 documents immutable status after a metadata-only fetch.
The embedding manual distinguishes the sole-head ancestry and exact WC commit
proof from strict preparation/checkout witnesses. Neither status nor fetch
completes the saved checkout pointer, captures disk files or moves a History
selection. Cold host integration remains a separate gate.

E-VAULT-BACKUP-030 documents capture-independent initialized transport and
immutable backup review/counts. The embedding manual names the pinned-reader
entry points, preserves existing Session compatibility and separates first
initialization from damaged existing state. Shared host orchestration and cold
applications remain separate from native and real transport source acceptance.

E-FORGE-CREDENTIAL-REPLACE-001 documents identity-checked token replacement
through the native account manager. Embedding guidance preserves opaque account
references, approved endpoint scope and concurrent metadata/credential guards.
Host admission and pending-publication holds remain application-owned; mock
provider transport does not qualify live sign-in or packaged host adoption.

# Workflow documentation

JST-DOC-001 and JST-DOC-002 apply to the native workflow profile. The authored
CLI guide is included in command help and generated parser references. API
references derive from the actual registered WorkflowService routes and schemas.
The guide describes separate metadata/source grants, explicit host admission,
operator-owned commands and environment secret references, pinned source export,
ordered evidence, cancellation and unknown-outcome recovery under JST-WF-001
through JST-WF-007. Version/format limits and live qualification gaps are
explicit.

The browser uses the owned Buzz-inspired view with public Design Core controls.
Documentation distinguishes native workflow YAML from runner-owned Actions YAML;
remote Forgejo runner registration/polling and ConnectRPC remain deferred.

E-WORKFLOW-CHOICES-001 updates the owning UI chapter and application review
under JST-DOC-002. It records cold trigger-data discovery, server profile/avatar
hydration, canonical thread ownership, highlighted native revset suggestions and
shared toast failures. Agents appear as unavailable author filters while the
backend message event contract supports authenticated human principals only.
These UI reads do not add runner protocol or agent-message execution support.

E-WORKFLOW-RUN-001 documents the Settings-style manual Run form, searchable
recorded source selectors and icon-bearing overview actions. Source lookups are
bounded and independently authorized. Bookmark selection records its unique
commit, operation changes clear dependent choices, and failures use shared retry
toasts. Unknown outcomes retain the original command and read-only source.

E-WORKFLOW-HISTORY-001 documents Workflows/History tabs, requester ownership
groups and profile hydration, task-style filtered history and exact URL-selected
run details. Header action tooltips, source identity controls, initially
collapsed sections and shared empty/toast states reuse maintained components.
Bounded loaded-row search, registered-definition discovery, publication pins and
removed workflow saved-link behaviour are explicit. M28 execution and visual
gates stay unchanged.

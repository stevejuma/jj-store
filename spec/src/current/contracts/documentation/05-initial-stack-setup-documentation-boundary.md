# Initial stack setup documentation boundary

The local technical guide MUST distinguish stable physical recovery admission
from live observation: the owning provider reuses the existing root/`.jj`
identity digest without reading current code, checkout metadata, ignore policy
or editor files. Document replacement/revocation refusal, read-only behavior and
the remaining original journal, registration and runtime gates.

Current-workspace documentation MUST distinguish selected public combination
catalogs from original command receipts and proposed private state. It explains
absent, ready, stale and pending readiness, profile/scope/resource bounds, and
the unimplemented registered runtime join. Existing-state projection and owned
DTOs cannot be described as a wired workspace picker or writable command flow.

Recovery documentation MUST distinguish owned public command projections from
runtime and HTTP composition. It explains exact stable scope/ID/digest lookup,
original preview/receipt validation, bounded actor-scoped pending discovery and
terminal history. Public results exclude private execution and do not install
current workspace snapshots. Service and server source review fingerprints MUST
cover this projection boundary. Cancellation identity validation does not
qualify durable cancellation execution or enable production controls.

The local technical guide records initial merge/WIP preparation and original
registered execution separately from dirty-work capture, membership/switching,
command transport and writable UI. Setup preserves unsnapshotted bytes in place;
its WIP tree retains the previous native checkout baseline. The implementation
plan and progress evidence keep the seven approved backend stages in progress.
No documentation review may imply automatic initialization on reads or enable an
unqualified command capability.

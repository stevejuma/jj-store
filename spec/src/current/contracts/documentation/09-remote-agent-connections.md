# Remote connection documentation

JST-DOC-001 documentation covers Add server, device-owned selection and restart
recovery, memory-only credentials, fixed-origin forwarding and caller-owned
agent sessions. Operator configuration names paired executables, fixed agent
definitions and principal allowlists independently of repository grants.

The manual identifies existing native WorkStore homes, native attachments,
private delegated workspaces and unchanged receipt recovery. It distinguishes
source/fixture and cold browser evidence from installed-provider, real-storage,
desktop and platform qualification. No shared deployment release is inferred.

The isolated acceptance runbook documents `remote-agents-acceptance.py`, paired
production executables, a built web root and optional copied privacy-rule cache.
It uses synthetic credentials and owns private temporary state/process cleanup.
Configuration documentation names the registered remote WebSocket Origin and
installation fence without weakening browser or token admission. M27 and
E-REMOTE-AGENTS-002 identify the macOS real-storage integration scope and the
separate installed-provider, Linux and desktop gates.

Operator guidance documents Agents → Manage server access, independent enrolled
`manage-agents` and `manage-identities` roles, reloadable saved/effective
definitions and allowlists, and explicit native repository Write onboarding.
Original-outcome recovery, same-principal grants and public profile/avatar
identification retain their separate authority. The installed Codex harness uses
two disposable local real-RustFS instances and existing prepared tooling; no
provider installation, credential copy or development reset is required.
Evidence must distinguish a passed operator UI from actual provider
prompt/publication, restart/revocation, Linux and desktop qualification.

E-APP-RELOAD-001 documents **Reload saved settings**, supported domains,
independent reload permission, unchanged listener/storage identity, per-domain
results and recovery of the original unknown request. Agent launch and Compute
relay changes can remain deferred until a worker/helper next starts. They do not
require a server restart. Deployment identity/access, TLS, listener, storage and
bundle paths remain startup-managed; backup/restore is not enabled.

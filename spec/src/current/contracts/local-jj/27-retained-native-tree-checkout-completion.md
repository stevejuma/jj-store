# Retained native tree-checkout completion

After sealed physical installation, the provider MAY complete the exact saved
tree plan's native metadata under the original foreground lease. It MUST first
select a canonical bounded private completion frame linked to the saved plan,
inventory, complete installed physical fingerprint and prepared native inode
identities. The canonical version-1 frame admits at most 64 KiB and carries
digests and stamps; original native bytes remain in the immutable plan. Stage
both native files before selecting the frame; partial staging or frame writes
resume only an exact byte prefix. Replace tree-state before checkout, sync both
selections, and never reacquire an upstream working-copy loader or initialize
absent native metadata.

Preserve unaffected file-state records and sparse patterns. Changed regular or
executable records use the installed inode's size and upstream-compatible signed
millisecond mtime; deleted records disappear. Sort records by native RepoPath
component ordering, select the exact candidate tree and clear stale Watchman
clock state. Only original fingerprints or exact prepared replacement inodes and
bytes may normalize the original witness; checkout-selected/tree-original state
is invalid. Fresh complete physical and retained-backup checks bracket both
replacements and acknowledgement. Reopening the original saved inputs loads the
provider frame without guessing a replacement command. Lost access, changed
policy, replaced metadata or editor changes fail with retained evidence.
Completion proves native checkout only: actual combination after-state, original
journal acknowledgement and writable transport remain separate gates.

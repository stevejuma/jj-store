# M15 additive collaboration publication

Threads and Reactions use independently selected canonical roots and immutable
complete-closure inventories. Native manifest format 5 adds optional roots and
state versions; local companion version 2 extends the owned ref envelope on
first feature use. Earlier formats remain byte-identical. Publication providers
retain original request receipts and expected-state checks; staging is
invisible. Cold recovery and copy audit all current and historical selected
roots, including raster assets and external AgentStore/ReviewStore/code
dependencies. Reducer 3 qualification precedes replicated collaboration
publication; unsupported origins fail closed. No replay executes agents or
fetches image bytes.

The local Thread and Reaction descriptors each select their own canonical root
and sorted complete content-ID-to-Git-blob inventory. Reads verify retained tree
membership, canonical identity, exact graph closure and external source
closures; they cannot read staged blobs or extra inventory entries. Agent and
review references retain the existing repository-bound bytes in separate
inventories. Portable code links retain exact qualified capsules; native code
IDs and stronger unqualified attribution fail closed in this profile.

Local typed commands derive the actor from device provenance, check selected
receipts before target/entity preconditions, and retry an expected-old-ref race
against all newly selected roots. Set/Clear/ResolveConflict and custom library
commands use the shared pure projector. Source/preview blobs remain reachable
after image replacement, retirement, process reopen and ordinary Git GC.
Existing sessions stay unlinked until an explicit link command. Reaction query
pages resolve current target visibility before returning actor slots, accept at
most 256 rows and four MiB, and require the captured metadata commit for a
continuation. Raw reaction records are not exposed by the local asset reader.
Capture-plus-binding publication and cold full-process CLI/UI acceptance remain
separate pending gates.

Explicit CreateAgentDiscussion validates an exact selected AgentMessage target
and retains its immutable baseline and event/content dependencies in the
ordinary ThreadStore. Human replies use existing message commands and receipts;
neither discussion nor reaction publication controls execution. Execution
feedback captures one authorized companion metadata commit and projects visible
reply revisions from that selection. The next explicit prompt can include those
replies as retained context; exact request replay never reads new feedback.
Provider/reopen qualification does not qualify a local browser Thread transport
or the broader cold local CLI/UI gate.

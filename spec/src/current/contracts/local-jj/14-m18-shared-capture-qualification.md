# M18 shared capture qualification

The [capture completion profile](../collaboration/index.md) strengthens the
shared normalization/publication engine used by this provider. Diagnostic-only
input and separately accepted partial tool updates need independent local
regressions without changing existing request/receipt framing. The initial
server discovery worker targets verified native repositories; serving ordinary
Git-backed folders does not enable transcript discovery or automatic hook
causality. Existing M13 portable evidence/review gates remain prerequisites for
broader local capture.

Evidence-only capture selects sanitized evidence and source/projection progress
without fictional sessions. Local reopen retains original receipts and permits
later source capture. Separate tool captures enrich selected prior content and
terminal state through the shared engine; request tags, intent framing and
companion publication authority remain unchanged.

Companion AgentStore supports only its canonical version-2 domain descriptor and
schema-2 transcript append-tail pages through the same strong Git blob
dependencies. Version-1 descriptors and schema-1 forward pages are rejected
without upgrade, rewrite or migration. Supported pinned tail manifests remain
independently readable after restart and Git collection. Current AgentRootV1,
chunk, manifest and portable provenance formats remain supported. First use of
an absent companion Agent domain still creates the current descriptor through
explicit authorized publication; this is distinct from legacy conversion.

The local provider derives the same opaque append witnesses from validated,
retained records in the explicitly selected companion snapshot. It reuses its
existing evidence-audit pass without a new authoritative index or metadata
write.

Bound diagnostic-only batches retain an explicit capture_gap Thread link through
the same atomic companion ref selection and complete external Agent closure. The
gap preserves original observed binding intent without a synthetic session or
primary assignment. Restart and Git collection retain the evidence and exact
receipt; later valid bound capture has independent observed preconditions.

Qualified common-native Codex alias adoption uses the same pinned shared
projector and V1 identity-join projection precondition. Different source
channels can enrich one selected session/tool without changing original IDs,
source cursors or receipt framing. Companion reopen and replay must preserve
both the original metadata pin and the joined result; ambiguous aliases retain
evidence and progress without an invented session. This shared projection
qualification does not enable automatic discovery for filesystem-only serving.

Directory reads of commits directly named by the selected view use a read-only
Git backend capability. Reads grant only exact parents, predecessors, tree terms
and tree entries reached from already-proven objects. Every backend read checks
current registration authorization, cancellation, path depth, object kind and
byte/work/deadline budgets before delegating. Commit visits are request-bounded;
no backend write, copy discovery or collection is available through this
capability. Historical point lookup follows bounded retained operation/view and
commit edges until the selected commit is proved. Deep lookup can still exhaust
this proof budget until its derived historical index is qualified.

Local `commit_summary` returns the exact selected commit object without graph
decorations. Local `file_at` requires commit, canonical path and exact file ID;
all must agree with a selected native tree term before content can be read.
These queries reuse scoped read capabilities, preserve explicit conflict terms
and do not admit unrelated Git objects. Legacy bare-ID reads retain their
membership checks. `include_last_change=false` returns file rows independently
of history. Optional attribution makes one shared jj-lib first-parent scan of at
most 64 steps, comparing tree terms without merged-parent reconstruction.
Integration commits are accepted. Unresolved rows return selected-commit
metadata labeled `snapshot`; confirmed path changes use `path_change`. All
returned IDs remain under the exact operation and fresh authorization. Quick
metadata finishes without continuation. Optional history mode reuses bounded JJ
file-history batches, retaining quick UI values while pending; neither mode
schedules changed-path maintenance. Source indexes, operation links, Git refs
and extra metadata remain unchanged. Ready core indexes may still prove
historical membership; bounded cold proofs retain their existing failure and
recovery behavior.

Managed JJ merged-parent file comparisons may retain bounded request-local
synthetic Git blobs, using canonical Git blob identities and read authorization.
These disappear with the request and its readers; source objects and refs remain
unchanged. No mutation capability is granted by this scratch content.

Local workspace windows and exact bookmark/workspace resolution consume only the
selected operation/view and returned target records. Neither needs a JJ index or
retained commit ancestry. Names are compared exactly, including case and
slashes; missing selections remain absent and must never fall back to another
target.

Local code-summary queries MUST use the metadata-only selected operation/view
facade and prove returned commit heads directly through those references. Read
only the requested first head window and return newest sampled committer
metadata with explicit incomplete-count status for unvisited ancestry or heads.
They MUST NOT open a graph repository, rebuild/import an index, traverse older
commits, read trees or reconcile operation heads. Current folder admission,
byte/work/cancellation bounds and exact operation pins remain mandatory.

Local review activity MAY reuse numeric facts at the exact selected Review root
and first reference window across reopened facades and unrelated companion
publications. Complete companion membership, retained blobs, canonical domain
closure and current folder identity remain fresh before reuse. Retain no
MetadataStore, companion Snapshot, source path or actor, and keep an independent
bounded cache lifetime. Empty reads must still leave identity and actor absent.

Operation log windows without an ID-prefix selector MUST walk bounded operation
metadata directly, without loading commits, trees, views or a commit index.
Native responses report `not_used` for the graph cache. Operation ordering,
parent/child selectors relative to `@`, filtering, pinned membership,
authorization and cancellation retain pinned JJ semantics. ID-prefix selectors
use a sorted retained-operation identity/fingerprint projection from explicit
preparation. Bind it to the exact selected operation and generation; resolve
prefixes by binary search while preserving missing/ambiguous and parent/child
selector semantics. Fresh operation metadata, current access and ordinary read
limits remain mandatory. Prefix membership MUST NOT rescan all ancestors, load
commits/trees or repair source indexes. Cold HTTP prefix queries return
exact-operation rebuild-required recovery. Local reads must not repair or
rewrite a damaged commit index as a side effect of reading operation metadata.

Selected historical commit summaries, directories and scoped file reads MUST
prove only the requested commit's retained membership. Follow exact commit
parent/predecessor links and the selected operation's retained ancestor views,
stop once the target is proved, and then follow only its requested tree path.
Membership proof retains IDs rather than commit bodies and MUST NOT load a
source commit index or read unrelated trees. Current authorization, byte, work,
visited-record and deadline limits apply throughout. Exhaustion remains an
explicit error pending prepared historical lookup; it cannot imply absence or
authorize a raw Git object. Later operations cannot grant access to commits when
reading an earlier selected operation.

Local prepared-history tasks MAY retain credential-free library handles under
shared native/local cache reservations. Bind the registered repository,
generation, metadata path and explicit retained operation before starting.
Duplicate live or retained-ready requests reuse their task; quota pressure may
evict the least recently used completed local generation. Active readers retain
its resident and full reservation until actual completion. Running and completed
lifetimes are separately bounded; expiry and teardown cancel live work, and
completed expiry releases capacity without a polling client. Preparation's first
authorization wait obeys the same cancellation/deadline as its worker. A
restarted service cannot revive an old task or silently select current heads.
This service facade alone does not advertise HTTP or browser preparation
capability.

Completed local generations participate in the same process-wide resident LRU as
native indexes. Memory pressure may release an idle completed handle and its
disk reservation before completed TTL expiry. Status and duplicate-start lookup
must prune evicted handles; selected reads return exact-operation
rebuild-required recovery. Keep executing reader handles charged until their
last owner exits and never substitute a later generation after eviction.

The LocalTrusted HTTP composition shares the native cache root and preparation
worker with local tasks. Log, detailed commit and evolution dispatch consume
prepared generations and return an explicit exact-operation rebuild-required
result when cold; it does not fall back to complete commit/tree preflight. Other
local query kinds keep their owned dispatch until their prepared reader is
qualified. Start/status/cancel transport preserves current registration checks
and independent source pins.

Scoped file/header and bookmark/workspace target reads MUST use the same owned
Git commit decoder as preparation, without GitBackend's extra import or table
reconciliation. Capture bounded source-table heads and parent framing, then seek
only the requested key and value. Do not materialize or hash unrelated values on
an interactive point read. Retain open source handles and check file identity,
size and nanosecond mtime/ctime before and after each seek; when those
timestamps are insufficient, fall back to bounded full checksums. Missing extra
records use JJ's header or synthetic change ID without writing a segment or
retention ref. Point lookup follows the source stacked-table format; it is not a
whole-file integrity report. Prepared generations still require full checksum
verification. The legacy complete-admission graph/difference paths retain their
separate qualification until replaced by the prepared reader.

Device-folder authorization and code/freshness snapshot capture MUST observe the
current owned companion ref through a lightweight identity read. Verify the
selected Git commit, tree and canonical state blob, root limits, declared tree
links and parent framing; do not read domain payloads or traverse retained
evidence merely to identify the repository. This observation exposes only the
repository and metadata-commit identity, never a domain Snapshot capability.
Missing or corrupt selected root data still fails. Domain reads and publication
retain their complete selected-closure validation, so an unavailable domain
cannot silently become valid through the identity path. No persisted format or
capacity ceiling changes.

Local selected file diffs, changed-path summaries and conflict descriptors MUST
use scoped operation/view membership and the read-only Git decoder. Prove only
the requested from/to or conflicted commit, then follow the selected tree paths
under ordinary query budgets. Do not preflight unrelated commits, trees or
retained operation views and do not repair source indexes/extra tables. Each
requested commit needs independent membership proof; Git object existence does
not grant authority. Deep historical membership may still require separately
qualified prepared lookup. Copy support remains the pinned Git backend profile.

Prepared local generations MUST derive selected-view visibility once during
bounded preparation, using only indexed parent edges. Retain the exact visible
commit membership and reverse bookmark/workspace annotations with the immutable
generation, and admit their memory before growth. Reuse them for log, detailed
commit and evolution responses instead of reconstructing visibility or scanning
all references per returned row. Change prefix ambiguity, target order, hidden
offsets and divergence retain pinned upstream index semantics; an index wrapper
must reject any different head selection. Each response supplies current access,
preserves the exact operation and ordinary limits, and hydrates only selected
commit records. Evolution follows bounded retained operation/predecessor edges
without loading older views, unrelated commits or trees. Cold detailed history
queries return exact-operation rebuild-required rather than complete preflight.
Before JJ's synchronous evolution visit, admit each operation's predecessor
batch and conservative squared queue work; oversized expansion fails explicitly
under the ordinary query budget. This bound does not reduce repository capacity
or increase ordinary limits. Prepared generations retain a canonical
operation/view digest. Fresh reads MUST agree with that capture, and guarded
upstream rereads must agree with the fresh selection. Changed source records
fail explicitly rather than combining old visibility/annotations with another
view. This check retains supported upstream normalization and adds no
authoritative source format or metadata write.

Local preparation MAY export a checksum-verified fixed-width operation-identity
projection from the already bounded ordered scratch tables. Charge its bytes
before writing and resident memory before allocation. The projection contains
only the selected operation, its retained ancestors and canonical operation
fingerprints, is disposable, and grants no source mutation or publication
capability.

Prepared operation prefix reads compare historical source metadata against
captured canonical fingerprints because SimpleOpStore does not hash operation
filenames. Fingerprint mismatch fails explicitly. Prefix resolution and
membership charge logarithmic lookup work; child suffixes retain the pinned
upstream bounded operation walk until indexed neighbor lookup is delivered.

Ready local generations MUST also supply point membership to selected historical
commit summaries, directory windows, scoped files, diffs, changed-path pages and
conflict descriptors. These reads reuse the exact operation/generation seal and
a fresh authorized scoped backend without creating a graph repository or walking
commit ancestry for proof. Tree/file authority still follows only proven commit
terms and canonical paths; both diff targets require independent membership.
Later-operation and unrelated Git objects remain excluded. When no ready
generation exists, these requests retain their bounded ordinary scoped reader,
so current files and headers need no preparation. Only a missing generation may
select that cold path; authorization, corrupt selection and reader errors must
not fall back. Complete large-scale and lifecycle qualification is deferred;
focused equivalence, low-visit and source-preservation regressions remain
required.

Prepared local generations MUST retain an ordered visible change-to-commit
projection constructed from JJ's index commit/change stream, without rehydrating
Git commit bodies. Admit membership, projection keys/targets and reverse labels
before allocation. Unfiltered Changes and All reference pages at that exact
operation MUST seek this projection and selected bookmarks before hydration,
including backward/deep anchors and exact change lookup. Preserve lexical keys,
divergence, sorted target identities, explicit conflict terms, workspace labels
and complete-result semantics; hydrate only the selected page's targets. Hidden
rewrites and later commits cannot become visible changes. These queries require
preparation when cold. A differently embedded reference operation remains
separate indexed-delivery work. No source or wire format changes; comprehensive
large-scale qualification stays deferred.

Prepared local reference filters MUST preserve whole-string Unicode lowercase
substring matching on the full reference key or any pinned target description.
Capture descriptions with the existing bounded commit read during preparation,
using the scoped decoder's lossy UTF-8 normalization. Store text and ordered
candidate postings on disk, with byte/work/cancellation and pre-growth disk and
resident admission. Intersect compact postings in lexical rank order, seek from
the requested anchor and verify exact text only for candidates' selected-view
targets. Historical hidden targets may narrow candidate lookup but MUST NOT
produce visible changes or satisfy a visible change's filter. Preserve removed
bookmark terms, divergence and forward/backward probes. Hydrate source metadata
only for returned rows. Empty bookmark/workspace pages remain independently
usable without preparation; filtered Bookmarks and Changes/All use existing
exact-operation preparation recovery. No complete matching set or source history
traversal is permitted on the prepared request path. Candidate work still
observes ordinary limits and MUST fail explicitly rather than returning a
partial result; retained continuation for extreme candidate frontiers remains
separate delivery work.

# Freshness producer ownership

State owners publish bounded, body-free semantic notices after accepted changes
and asynchronous settlement. Capture observations suppress scheduler-only phase
and resident-frame churn while retaining pause, drain, availability, selected
source, import and queue progress. Local watcher hints never establish committed
state; shared bounded heads/companion checks validate their meaning and cover
missed physical notifications. No browser poll is needed while the advertised
application feed is healthy. Exact task and request receipts remain
authoritative.

Local reference requests may select a retained ancestor operation independently
of their outer read operation. Prove source membership through bounded read-only
operation parent metadata, with current registration authorization, before
consulting prepared data. No view or Git commit walk establishes that relation.
Prepared windows use only the source's exact generation and selection seal; a
ready generation cannot admit newer or unrelated operations. Cold indexed
references identify the source in the existing rebuild-required snapshot.
Successful response snapshots and signed continuations remain bound to the outer
operation and full request, while reference pages identify the source. Empty
bookmark and workspace windows keep metadata-only source reads.

Prepared local operation selectors with child (`+`) steps MUST seek an exact
operation-bound parent/child projection instead of scanning history from its
head. Preserve upstream prefix, parent/child, empty and ambiguity semantics for
every mixed suffix. Only retained ancestors participate; later operations never
become children in an old prepared snapshot. Source fingerprints and current
authorization remain mandatory for selected metadata. Admit disk growth and flat
resident edge allocations before construction/decoding. Old disposable artifacts
without the projection require explicit preparation for ID-prefix child
selection; no full history fallback is allowed. Current-operation relative
selectors retain their bounded metadata-only cold reader and reuse a ready
neighbor projection opportunistically.

Prepared local operation graph pages MUST admit the selected operation using its
fresh canonical operation fingerprint, independently of the selected view. Both
unfiltered and metadata-filtered pages may reuse the ready identity and neighbor
projection while retaining their bounded cold behavior where supported. No view,
Git object, commit-index load or scoped commit grant is needed for an
operation-only page. Current registration authorization, repository/path
binding, generation and retained operation membership remain mandatory.
Historical row metadata must agree with its captured fingerprint. Code,
reference and operation detail readers retain their combined operation/view
seal; unavailable or replaced views cannot inherit authority from metadata-only
admission. Missing prepared data may select a supported cold reader; corrupt or
denied reads cannot.

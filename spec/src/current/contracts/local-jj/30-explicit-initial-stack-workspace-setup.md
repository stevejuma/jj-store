# Explicit initial stack workspace setup

Only an explicitly prepared Setup command may create the first combination. The
provider MUST resolve the exact selected local or already-known remote bookmark
in the pinned source view; missing, moved or conflicted targets cannot be
substituted with a guessed branch or fetched state. The initial profile requires
resolved source and target trees. Under the existing foreground lease and
complete fresh physical guard, create an unpublished internal merge commit whose
sole parent is the target and whose tree equals that target, then a new WIP
child whose exact tree equals the current named workspace commit. Preserve all
original operation/history/code records, bookmark/tag/Git/remote facts and other
workspace selections. Both new commits have distinct stable identities; setup
rewrites or abandons no original commit.

Physical tracked edits, deletions, untracked/ignored obstacles, symlinks and
empty directories remain unchanged. Setup preserves unsnapshotted edits in
place; it does not claim they are already stored in the WIP tree. Membership and
switching MUST capture and preserve that complete unfinished work before moving
away. Preview and retention select no operation head or checkout state. Actual
publication uses the retained original journal, foreground lock and typed native
proof; unchanged-tree checkout may then update only the operation pointer.

Server preparation MUST derive the first after-state from that exact retained
provider archive, never from client snapshots. It assigns one server-owned
combination identity at generation 1, validates the named WIP/merge/target
closure, stages its bound after-state before publication and acknowledges the
command only after native checkout and combination selection. Interrupted
preparation resumes its saved candidate/identity without generating
replacements. Current registration, complete source/code/physical selection and
absence of a selected combination guard unpublished apply. Already published or
terminal outcomes use only original recovery, never reannounce lost selection or
recreate missing staged state. Setup adds no automatic initialization on a read
and does not qualify membership/switching, content transfer, graph actions or
transport.

Stack creation makes an independent bookmark at the target or a dependent
bookmark at a selected applied head, then applies it. Positional branch creation
labels the selected commit or its single parent without rewriting content.
Renaming updates applied bookmark names in all saved configurations. Rewording
and empty-commit insertion use native rewrite/rebase and preserve merge/WIP
change identities. Target bookmark names and reserved retention refs remain
protected. Bounded point inspection of displayed commits reports configured JJ
immutable/target protection; hidden objects cannot be mutation sources.

The first commit on a bookmark still pointing at the workspace target MUST fork
from that target without rewriting unrelated target children. Explicitly
retarget only the retained merges applying that bookmark; later commits use
normal insertion and descendant propagation. Empty Commit selections create an
empty commit. Refresh must not reconstruct these already-correct parent sets.

Selected whole files can move between exact visible mutable commits and WIP
through native squash, retaining emptied sources. Split extracts selected
content into a new child and advances source head bookmarks; inline edit rewords
and may squash additional selected files. Sources bind exact
operation/commit/path identities, and merge/root/immutable shapes remain
rejected. New commit selections may come from WIP or displayed mutable commits.
No staging state or additional merge reconstruction is persisted.

Native local Stacks hunk selections are issued by the guarded read-only POST
`/v1/local/repos/{repo}/stacks/hunks`. Tokens bind native source change
identity, canonical path and complete before/after bytes; apply rederives them
at the exact operation/configuration pin. Client patches and display-only IDs
are rejected. Partial text deltas use native squash with emptied sources
retained, without reconstructing the megamerge. Binary, conflict, mode/type and
bounded-diff limits remain whole-file-only. Net branch comparisons remain
presentation-only.

Local graph commands use native `move_commits` insertion/reordering and full
`squash_commits` for squash/uncommit. WIP is retained as a native child; graph
rewrites do not reconstruct the merge. Branch squash/rebase discovers at most
500 commits in its segment and stops at the next user bookmark boundary. Visible
source identity, configured immutability and workspace-target protection are
validated at preview and apply; retention commits are not graph sources.

Branch rebases move the segment root with descendants. Single-revision moves
detach ordinary children as JJ does; if this detaches a saved applied edge,
native rebase restores that edge on the existing retained merge change. This
preserves its identity and WIP delta without constructing a replacement merge.

The ordinary local Stacks mutation profile now includes native bookmark deletion
(top bookmark only; lower bookmarks and commits retained), abandonment, selected
whole-file/native-hunk WIP discard, and complete native text-conflict
resolution. Conflict terms are read lazily through guarded POST
`stacks/conflict`; ordered three-term text conflicts use the existing Merge
Editor. Multi-sided text conflicts expose bounded ordered versions for in-app
pairwise comparison in the same editable Merge Editor. Each comparison uses the
reviewed result and the next selected native version with its actual preceding
negative term; pair completion does not stage the whole native conflict. The
user explicitly stages the reviewed complete text before preview. Structural,
mode-conflicted, binary and oversized conflicts retain native values with
explicit unsupported reasons. Conflict paths are bounded to 50 per current read.

Undo/Redo restores the native repository operation stack, including CLI work,
with native descriptions and remote tracking semantics. Current Git bookkeeping
is retained, as in JJ. TOML is not an Undo journal. Missing or restored
references remain visible as unavailable choices/reasons; Refresh and Switch
never rebuild membership automatically. Explicit Reapply saved branches
reconciles membership and preserves WIP. Operation/config/source guards and
unknown-outcome inspection remain required. Production file dragging uses exact
loaded source/path pairs; partial dragging uses issued native hunk tokens. Net
branch comparisons remain read-only. Undo/Redo remains available without a
selected named workspace.

Production dependent branch segments derive from loaded native parent links and
local bookmark annotations, with one bounded continuation for the exact
advertised top head/target range. Only the lowest displayed segment loads more.
Each branch’s inline net files compare its own lower boundary and head; an
unproven paginated boundary remains unavailable until more history is loaded.
Merge/elided ancestry retains the provider graph without invented linear
boundaries. Visible applied lanes load their own bounded pages; other repository
history stays unloaded. Aliases do not duplicate commit rows within a lane.
Derived top-level stacks own columns; branch identities remain independent for
drafts, selections and actions. Dependent and alias bookmarks are represented
inside their containing stack, rather than as duplicate picker entries.

Local Stacks bounded history MUST use the managed code index when available,
with the same exact-operation visibility, paging and authorization as JJ Log. An
absent generation starts normal bounded preparation; a ready generation MUST
serve StackHistory rather than repeatedly requesting the older graph index. The
explicit prepared-index path remains supported for compatibility.

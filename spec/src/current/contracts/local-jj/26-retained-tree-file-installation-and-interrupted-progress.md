# Retained tree-file installation and interrupted progress

After exact retained head publication, the private provider MAY install the
saved tree plan's resolved regular/executable file effects. It MUST bind
canonical provider-owned progress to that plan, original complete inventory and
private staging directory identity under the original foreground lease. Verify
original retained effects, checkout/tree-state bytes, policy, access and source
identities before initialization. Fresh complete observations use the service
guard's existing admission, authorization and deadline; observing current data
is not a write or completion proof.

Before every physical transition, sync its exact intent. Prepare candidate files
and missing parent directories privately and select them with
descriptor-relative atomic no-replace moves. Move originals into unique retained
private backups before selecting replacements; never overwrite editor-created
targets or delete backups. Reject cross-device transitions before working-file
writes. Interrupted retry may infer only the saved intent's exact known source
or destination inode, content, size, mode and modification time. Only
rename-induced ctime may differ for moved files. Normalize directory
size/timestamps only for exact touched parent identities while comparing the
complete namespace; unaffected files and directories, ignored/untracked entries
and private backups remain guarded.

Progress framing is canonical version 1 and bounded to 32 MiB. Its original
inventory and maximum intermediate namespace each remain within 4097 records.
Partial staging accepts only exact retained byte prefixes before progress
selection. Checks bracket each move and acknowledgement; cancellation retains
worker admission and foreground coordination until exit. Replay verifies all
selected effects and backups without repeating a completed move. The sealed
result proves only physical files installed, preserving native checkout and
tree-state bytes. It MUST NOT acknowledge a command, update a combination or
enable writable transport. Native metadata completion and complete durable
after-state remain separate required gates.

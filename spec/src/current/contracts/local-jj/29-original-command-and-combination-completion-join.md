# Original command and combination completion join

Before publication, coordinated local execution MUST stage the exact
provider-derived combination after-state and save its installation-private
binding in the original authenticated journal. The domain-separated binding
covers scope, principal, complete preview, prior revision, complete after-state
and acknowledged retention. Journal-then-combination lock order applies. An
interruption after combination staging but before journal linkage resumes only
that original staged record; missing selected records cannot be recreated from
caller input. No new binding may be attached after Prepared. Exact historical
replay never selects an earlier after-state over current state.

Journal version 6 adds optional combination binding and native completion
references. Versions 1–5 retain absent-field serialization and original reads.
Completion linkage requires the saved combination binding and the exact sealed
provider proof: unchanged checkout binds its saved witness; changed-tree
checkout binds its saved plan, full inventory, native completion frame and
verified physical fingerprint. Saving native completion leaves the public
receipt Published with checkout Required or Blocked. It is not command success.

After fresh provider verification, select and sync only the matching original
combination record, then select the journal's verified receipt last. Retry after
selection or acknowledgement loss syncs the same record and cannot rewind later
state. Public transitions and legacy finish cannot bypass this ordering for a
bound command. Rejected unpublished updates remain discardable, while terminal
requests cannot gain completion evidence. New records cannot inject a binding or
completion during initial journal admission. The existing 32-KiB execution
reservation includes these bounded digest-only references; no capacity eviction
or public wire change is introduced.

This join qualifies durable coordination of provider proofs, not setup,
merge/WIP generation, membership commands or writable transport. Production
Stacks remains read-only until those owning engines and cold command/UI flows
qualify. Test-generated candidates and combination snapshots are explicitly
coordination fixtures, not a complete combination engine.

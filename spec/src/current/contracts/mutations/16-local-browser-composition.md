# Local browser composition

Device folder registration is an explicit LocalTrusted administrative write. Its
request journal precedes companion initialization, retains the same original
request through unknown outcomes and adopts the existing selected identity.
Removal affects only installation bindings. Local WorkStore browser commands
reuse existing receipt-first provider semantics; code mutations remain
unavailable in this slice.

Registration work and its blocking cross-process lease run on an isolated worker
so concurrent in-process requests cannot block the async runtime that completes
initialization. Typed read POST requests have no publication capability.

Local browser WorkStore commands dispatch through the existing companion
provider rather than native code mutation authority. They retain the original
request identity in transport unknown outcomes, use CLI actor provenance and
validate exact entity versions. Code commands remain disabled for this profile.

Recorded AgentStore browser POSTs and local freshness streams are read-only
queries of committed companion metadata and operation heads. They cannot install
hooks, record agents, reconcile heads or advance the displayed selection.

Local folder reconnect is a revision-checked device-binding update only. First
Add journals the proposed repository identity before initialization; retries
cannot initialize another identity after interruption.

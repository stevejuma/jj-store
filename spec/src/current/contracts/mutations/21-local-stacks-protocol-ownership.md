# Local stacks protocol ownership

The private physical projection compares complete bounded observations against
an exact provider working-copy baseline using raw-content digests and modes.
Tracked paths cannot become untracked through ignore rules. Untracked candidate
additions and ignored files remain checkout obstacles. Captured `.gitignore`
bytes must match their physical digest; symlink ignore files fail explicitly.
This projection is not a JJ snapshot, active combination assignment, issued
selection or executable preparation. Binding mismatches, malformed/duplicate
paths, limits and caller cancellation return no partial result. Capturing
global/exclude policy and proving current checkout/sparse state are now private
provider inputs. The service observation owner verifies identical witnesses
before and after the physical scan and current authorization before returning.

The physical observation owner MAY supply a trusted unchanged-checkout guard
through the existing complete bounded scanner. It MUST share physical admission,
resolve only its registered root/access owner, validate repository, generation
and physical-workspace identity, and compare the full original fingerprint.
Ignored, untracked, symlink, content/mode and directory changes remain part of
that guard; metadata-only pointer effects cannot weaken its scope.
Authorization, deadline and cancellation remain current throughout the scan, and
canceled work retains admission until the blocking worker exits. This guard
alone does not authorize a command, infer setup or enable runtime writes. For
tree-changing recovery, the same guard MAY capture an owned bounded original
inventory. File fingerprints and complete directory stamps MUST reproduce the
existing physical fingerprint without changing its version or ordinary scan
limits. The private inventory carries no file contents, credential, absolute
source path, selection token or write proof. Capture shares the existing
non-queuing scanner admission and authorization/cancellation lifetime;
unavailable capabilities fail rather than substituting a partial inventory.
Durable original-request selection and provider-owned progress remain separate
execution gates.

Sparse-excluded tracked paths do not become deletions; present outside-sparse
paths remain obstacles and cannot become candidate additions. Admission and
deadlines cover the complete observation, including a canceled blocking worker.
The registered read transport exposes bounded version-1 summaries, exact
operation/view/WC identities and read fingerprints, without policy bytes,
contents, content-selection tokens or preparations. Neither these summaries nor
an HTTP success grant write eligibility. Active-combination assignment,
foreground locking, durable preparation and fresh apply preconditions remain
separate execution prerequisites.

Under JST-LOCAL-005 and JST-UI-020, `stack_workspace` owns typed version-1
execution selection, prepare/apply and receipt records independently of catalog
presentation. Native and Git SHA-1 commit/tree identities remain explicit
variants. Upstream JJ imports and code preparation stay in the existing JJ
provider; this owned protocol does not publish native state or perform checkout.
Exact intent digests cover all physical and code preconditions and the complete
command, while replay uses the original request identity. Apply binds an exact
preparation. Whole-file/hunk claims are server-issued and retained; validating a
claim neither accepts client patch text nor grants access. Deleting a bookmark
and abandoning a stack segment have distinct command variants. Above/below
placement binds an explicit anchor and parent boundary. Guarded undo names the
original application request/operation. Missing executable provider capability
keeps the corresponding action unavailable.

Receipts never masquerade as current view snapshots. Published code with
incomplete checkout remains pending recovery, and retired commands cannot be
executed through replay. Unknown publication cannot be treated as rejection or a
new command. Persistent provider/journal and transport qualification are
required before these records enable production mutation controls.

The owned command-recovery DTOs retain stable physical/profile scope separately
from live generations. Status binds original ID and intent digest; cancellation
also binds the original preparation and accepts no replacement selection or
command. Public command results validate complete preview/receipt linkage and
exclude private server execution records. Pending discovery rejects terminal
receipts, duplicate IDs, scope mismatch and resource-limit violations. These
contracts grant no execution or cancellation authority; executable admission,
durable cancellation coordination and HTTP composition remain separate gates.

Owned current-workspace discovery retains exact registration/operation input and
observed selection separately from historical receipts. It distinguishes absent,
ready, stale and pending state, and validates scoped selected catalog
membership, code profiles and response bounds. Public catalog projection strips
private retained objects and proposed after-state. Neither catalog readiness nor
the existence of these DTOs authorizes a command; registered runtime joins and
transport/executor acceptance remain required.

Grouped local Stacks Unapply validates the entire explicitly applied bookmark
set under one operation/configuration guard and uses one native transaction.
Membership and target changes rewrite the retained app-owned megamerge from the
target plus distinct applied tips, preserving WIP delta and change identities.
Reconciliation previews list conservatively proven obsolete merge heads before
retirement; ordinary reads and refresh never repair repository graphs. Native
operation history remains the recovery path.

## External forge effects

JST-FORGE-001/007 owns ordinary-local stack publication through the shared
jj-store-jj orchestration. Device-local forge receipts record external effects;
they do not use or replace native command WAL, manifest CAS, WorkStore or
repository Undo/Redo. Restack reuses the native local transaction and physical
workspace guard. Its internal command is excluded from the public local-command
Serde/schema union; only the forge planner can admit it. An unknown local
rewrite is retained for inspection and never automatically repeated.

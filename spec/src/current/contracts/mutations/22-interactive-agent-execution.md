# Interactive agent execution

E-CHAT-INSPECTOR-001 confirms JST-MUT-001 unchanged. Optional read-only line
counts accompany the existing workspace observation and its selection fence.
They neither snapshot files nor create a command or publication receipt. Legacy
entries omit unknown counts; no mutation or independent code authorization is
introduced by inspector tabs, icons or statistics.

Intentional Thread creation and Codebase edits use the same service authority;
see [Thread workspace API](../api/44-thread-workspaces.md). Agent sends validate
the exact committed membership and selected subset before preparing workspaces.
Internal conversation containers remain separate from user Thread assignments.

JST-COLLAB-031 through JST-COLLAB-033 add owned service contracts for agent
setup, targets, explicit launches, prompts, current permission decisions,
lifecycle commands and stable request outcomes. Durable commands survive browser
disconnect. Receipts distinguish admitted, completed, refused and unknown states
without re-dispatch. JJ providers and AgentStore publication remain separate
owned interfaces.

JST-MUT-001 remains unchanged by the read-only managed capture/workspace status
projections. Identity joins and repository navigation neither create a command
intent nor start, resume, configure or prompt an agent. Ordinary discussion
continues to use exact native session/message targets. Original mutation
requests, authorization, conditional setup revisions, unknown outcomes and
receipt recovery retain their existing formats and behavior.

Explicit runtime installation is an installation-owned side effect, never a
repository mutation. Its original intent is privately journaled before npm
starts. Duplicate IDs return the retained receipt; changed intents conflict.
Installations serialize and refuse while an agent process is open. Unselected
staging directories never participate in discovery. Successful verification,
selection and completed receipt share one atomic journal write. A service
restart marks unselected interrupted installs as interrupted without replay;
only a new explicit command may prepare another directory. Unknown browser
outcomes query the original receipt and never resend installation automatically.

metadata CLI work uses existing WorkStore commands, versions and stable request
identities.

Workspace inspection is a read capability under JST-MUT-001: session and code
repository admission are independent, roots are server-owned and no observation
advances repository authority. Current observations retain selection
fingerprints and stale pagination fences. Inspection adds no review publication
authority.

Controller-owned prompt queuing captures the authorized workspace start only
when that exact request becomes eligible to dispatch. Proven pre-dispatch
failure releases its delivery reservation while retaining the request outcome.
Queued cancellation sends no prompt. Uncertain physical effects and restart
retain their original outcomes without replay; code-repository snapshots remain
independent from canonical transcript publication.

Repository-qualified review references add a trusted explicit read capability to
conversation publication under JST-MUT-001. Every new publication attempt
resolves the exact immutable review revision and original evidence with separate
code-repository authorization. Generic calls without this capability refuse the
reference. Receipt replay is stable; cached prompt source context still requires
current source permission. No home command mutates the foreign ReviewStore.

File draft publication is deferred until the queued prompt is eligible. A shared
workspace-dispatch guard covers capture and the gap before the started
acknowledgement. Busy sources leave the prompt queued and cancellation remains
available. All current fingerprints are checked before the first snapshot; every
captured file is checked again before any review publication. Each draft has a
stable review receipt, and partial publication retains its exact frozen
commands. An explicit retry can finish publication from completed captures; it
never replays admitted prompts or repeats a snapshot whose physical outcome is
unknown.

# Publication and recovery

The WAL facade exposes a pure normalized tool-alias lookup for timing reads from
selected sanitized observations. It reuses the owning AgentStore normalizer and
returns a native ID only for one unambiguous matching tool target. The lookup
cannot read storage, acquire a source, stage objects or publish state; immutable
evidence, request identities and capture formats remain unchanged.

Task comment reaction publication reads the Work root from the same captured
manifest base as ReactionStore and selects only the existing Reaction
transition. The shared authorized target reader validates Work state and
repository scope before resolving exact comment membership and visibility.
Root-keyed read reuse accounts for Work object and byte bounds; it cannot
introduce credentials, staged data or new publication authority.

Validated Agent and Review read selections may be detached from a coordinator as
immutable repository-bound root and membership data. Shared read caches and
collaboration pins retain these data-only selections, never a request guard or
credential. Resolving bodies attaches the current request's coordinator to the
validated selection after checking repository identity. Cold materialization
still performs the existing complete closure and native dependency audit.

Human reply parent revisions are retained as collaboration closure dependencies
through native publication, cold recovery and manifest-last copy; a UI reply
never substitutes a display position for this reference.

Native prepared capture requests may carry an explicit optional Thread binding
and server-chosen acceptance time. The absent field is omitted, preserving the
legacy intent encoding. Binding validates one real session replacement or an
explicit diagnostic-only source/projection pair selected by the same Agent delta
and selects Agent plus Thread roots in one manifest CAS. Both domains authorize
before receipt replay; the source manifest is privately pinned through CAS and
reloaded after a race. Matching receipts survive later Thread changes and
unknown outcomes retain original request/publication IDs. Replicated code
remains gated on reducer 3.

Upload objects, validate full dependency closure against a certified base,
upload inventory/result/candidate, then CAS the manifest. No receipt embeds its
future log digest. Manifest revision differs from publication sequence, and an
epoch identifies an authority lineage without itself fencing an old writer. No
destructive GC, automated promotion, or multi-writer serving in v1.

Shared AgentStore projection and catalog edits stage immutable objects through
owned repository-bound interfaces. They do not select native or local roots.
Native adapters retain all manifest guards and receipts; the local companion
adapter admits only immutable domain records and publishes through its separate
expected-old-value ref protocol. Record framing and native authority are
unchanged.

Native tool-result projection reads only selected source-scoped aliases or
qualified common-native Codex or OpenCode proofs and the selected session/tool
snapshots. It cannot adopt staged or foreign-session calls. New source aliases
and transient activity references may adopt one unambiguous accepted target;
existing records and prepared requests remain unchanged. Ambiguous or incomplete
alias lookup retains diagnostic evidence/source receipts without fictional
session edits. Matched result-only batches replace the existing session
cumulatively; prior roots remain readable and publication still requires
complete closure audit, authorization and manifest/ref CAS. Result presence does
not assert successful execution or change session lifecycle.

Qualified common-alias captures additionally edit the V1 projection catalog key
`codex-native-alias-join/v1` or `opencode-native-alias-join/v1`, preserving each
integration's selected expected object. This common precondition serializes new
identity adoption across the integration's product profiles and capture sources.
Concurrent stale preparation fails before publication rather than creating a
second native session. Product-specific projections, request framing, prior
prepared intents and receipt identity remain unchanged. Legacy prepared requests
can retain prior behavior; any resulting duplicate aliases are reported as
conflicts by subsequent common lookup, never silently consolidated.

Portable agent objects expose capsule dependencies separately from native
retention roots. Native staging and recovery reject unsupported portable
evidence. Local descriptor V2 selects a canonical capsule inventory with the
root and retains every declared Git commit and nonstandard tree dependency; only
the current descriptor V2 is supported. The shared provenance reducer can stage
records and relation pages but cannot publish either provider's state.

ReviewStore catalog editing and bounded reads use owned repository-bound
immutable object and pinned snapshot interfaces. Native wrappers retain full
root/thread cross-object audit, authorization, receipts and manifest selection.
The shared editor returns a root value; it cannot stage a publication or select
repository state. Alternative providers must audit the complete root before
publication and recovery. The shared ReviewProjector also stages typed commands
and audits complete review roots without publication. Native adapters verify the
returned external code and AgentStore dependency closure and retain
authorization, receipt-first replay and manifest CAS around the shared
projection.

Independent conversion builds complete destination domain catalogs without
publication capability. Rebuilt catalogs obey the same canonical radix rules and
bounded closure audits as ordinary edits. Final selection still requires the
existing manifest or companion ref CAS; archives and staging are invisible.

Independent conversion destinations reconstruct each supported historical
selection through authorized domain publication in private staging. The native
manifest is installed only after all immutable destination dependencies;
retained receipts establish completion without overwriting later destination
edits.

## Public release integration

Rust 1.99 atomic update naming and equivalent test-fixture iteration preserve manifest CAS, stable request identities, receipts and recovery. Public package metadata does not alter native codec or WAL formats.

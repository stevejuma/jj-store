# Retained Git interoperability domain

Git interoperability adds an optional independently versioned domain selected by
the shared manifest CAS. Its immutable radix catalog retains verified raw Git
object descriptors and native/Git representation associations. Descriptors
strongly reference native streamed file payloads; associations strongly retain
their native revisions and required Git objects. Recovery and native copy walk
these selected records and every retained historical domain root. Activation
uses format 4 without changing native identities or existing domain versions.
The Git origin reducer publishes immutable facts on code repositories; WorkStore
retains its frozen ledger.

Git acceptance uses the native guarded publication path with a typed immutable
record delta. Its digest binds both the native transition and Git facts, and one
manifest CAS selects the code heads, Git root, retained inventory and receipt.
The immutable delta is re-applied to current Git facts after CAS contention;
conflicting record identities fail without overwriting evidence. Git-only
acceptance leaves code freshness unchanged. Code origins carry the complete
selected Git root and native dependency closure.

Git push intent and event records retain frozen source/native dependencies,
causal observations, an authenticated executor and exact destination leases.
Staging validates their complete catalog closure and immutable identity.
Prepared, transport-started, per-ref result and applied records are separate
manifest-selected facts. An applied record requires satisfied result evidence
and the exact accepted observation. Native code undo cannot discard these
external facts, and cold recovery or copy never schedules external transport.

Git-origin reduction forms deterministic immutable unions, retaining all causal
alternatives. The owned native validator checks conversion and frozen-view
evidence; new intents prove accepted code ancestry rather than staged inventory.
Git data transfer never admits authority records or device executable
configuration. Cold copy retains every authored Git root in accepted-origin
history and seeds.

Git event admission checks the previously selected catalog, so a stage cannot
introduce its intent or event predecessors in the same CAS. Cumulative origins
consume those stages in causal order; explicit first-origin baseline hydration
preserves historical facts. A non-code origin cannot name published code
operations or use inventory membership to create source authority.

Git stage acceptance qualifies unknown manifest outcomes both before and after
write at activation, prepared, transport-started, result-recorded and applied
boundaries. Cold recovery exposes the old or wholly selected next catalog;
replaying each stable request produces one domain increment and a stable
receipt. This memory fault evidence does not substitute for real RustFS
qualification.

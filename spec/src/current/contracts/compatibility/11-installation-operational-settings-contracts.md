# Installation operational settings contracts

Additive version-1 local settings DTOs and `local_settings_management` advertise
conditional service/protection/replication edits independently of capture
runtime health. Configuration format 2, native storage, manifest/WAL and
credential formats remain unchanged. Search DTOs include all existing
worker/extraction limits; old omitted fields use their established defaults.
Generated contracts and actual LocalTrusted HTTP acceptance cover strict
actor-free input, saved versus effective snapshots, conflicts and current
authority rejection.

The opt-in local capture extension adds Cursor Desktop 3.22.7, a distinct Cursor
CLI 2026.09.26-dd393fe profile and OpenCode read-only API 1.18.30 to editable
settings. The optional API endpoint is credential-free literal loopback.
Generated contracts support five product profiles; exported OpenCode history
remains withheld. Runtime qualification is recorded independently of
configuration saves.

Cursor's distinct JSONL envelope uses the qualified product version, exact
native session UUID and source-derived complete-prefix record key. Existing
Codex JSONL envelopes and identities retain their byte encoding. Native Cursor
message/tool IDs, result states and timestamps are never invented. Source
admission markers bind the exact Cursor witness; registry format remains 1.
Runtime coverage supports four file profiles and one read-only API lane.

Native browser creation uses existing native object, manifest and WAL formats.
Its private installation request journal is version 1 and retains generated
repository/epoch identities before provisioning. It does not change the JJ
0.45.1 SHA-1 companion profile or create a working copy.

Path windows add optional `include_last_change`, defaulting to true for existing
clients. Row-only responses use the additive `not_requested` attribution reason;
cursor fingerprints include this mode. Local code queries add `commit_summary`
and `file_at` variants; existing bare-ID and detailed-commit requests retain
their contracts. Updated clients use the new variants only with this server
version. Native/local persisted identities, companion framing and manifest/WAL
formats remain unchanged. Generated contracts and exact cursor consumers qualify
these additions independently of large-history preparation.

Version-1 reference requests add optional `exact` and a `workspaces` kind with
named workspace response rows. Existing bookmark/change forms retain their
meaning. Updated browser startup requests bounded bookmark/workspace windows
separately; it does not reinterpret an incomplete page as a complete inventory.

Operation metadata pages may report graph-cache state `not_used`. Its zero cache
counters mean no cache observation was needed, not that retained caches were
removed. Graph node identities, selectors and paging fields are unchanged; no
native, WAL or companion persistence format changes.

Local code capabilities add `index_tasks` and three local preparation routes.
Cold local log requests return409 `index_rebuild_required` with the additive
`local_snapshot` error field. Updated clients validate that local pin and retry
only after exact-operation preparation; they never reinterpret it as a native
epoch. Start/status/cancel responses use the local task DTO, and cancellation is
bodyless. Generated contracts and actual HTTP responses qualify these additions;
native routes, persisted identities and companion formats remain unchanged.

Local prepared generations add the disposable `local-reference-filter` redb4.3.0
file and its SHA-256 sidecar. Its `JSTLRF1` metadata binds the selected 64-byte
operation and lexical row count. Text lengths, lowercase text and sparse/dense
4096-row substring postings are derived only; they change no native, companion,
WAL, receipt, cursor or public DTO format. Upstream JJ format6 index files
remain byte-identical and independently verified. Cache loss uses existing
preparation; this local artifact is never imported into source JJ metadata.

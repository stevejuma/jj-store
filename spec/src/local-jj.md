# Local Git-backed JJ collaboration

Local task comment reactions resolve only visible exact comment versions in the
same committed companion selection as ReactionStore, with matching task
membership. Reaction writes retain other domain selections and task versions;
edits and tombstones reject old targets. Cold reopen, Git GC, receipt replay and
exact observed clear use the shared typed domain without synthetic Threads. The
local browser's existing collaboration capability gate remains separate.

The companion retains exact human reply parent revisions in the owned Git
closure; absent reply fields preserve existing canonical message and intent
bytes.

Explicit local BoundCapture carries the exact observed Thread version and
primary assignment with the original sanitized batch/profile. It retains one
real session replacement or a validated diagnostic-only capture gap, stages the
shared link without changing lifecycle and selects Agent and Thread descriptors
in one companion ref CAS. The Thread descriptor audits and retains the complete
newly staged session closure before selection. Matching receipt replay precedes
entity/source preconditions; stale bindings select neither root. The private
spool retains this original bound request across unknown outcomes. Legacy
unlinked capture tags, field order and receipts remain unchanged.

M13 adds an owned companion metadata store to ordinary Git-backed JJ
repositories. Upstream GitBackend and JJ operation publication remain code
authority. Native repositories continue to use their existing manifest, WAL and
immutable objects. The local profile shares the domain models, service policy
and presentation.

Explicit local capture shares the selected-alias tool-result resolver with the
native provider. A result-only request cumulatively replaces a verified existing
session while preserving lifecycle, previous snapshots and original receipts
across reopen. This does not enable automatic readers for local Git folders.

The shared projector also adopts qualified common native OpenCode session,
message and tool aliases across explicitly supplied hook/API/export evidence.
Case-sensitive native identity, complete selected-alias coverage and verified
parent-session/tool targets are required. Ambiguous prior targets retain source
receipts and diagnostic evidence while withholding logical entity edits. New
captures select the integration's common projection precondition through the
local expected-old-value publication; original receipts and historical roots
retain their prior interpretation.

## Publication profile

Initial qualification is JJ 0.45.1, Git SHA-1 and macOS ARM64. The owned ref is
outside branches, tags and upstream `refs/jj`; ordinary Git and JJ network
commands do not transfer it.

Metadata commits retain preceding selected metadata commits through parent
edges. Domain bytes and immutable evidence use actual tree entries; retained
code commits use parent edges and nonstandard tree/blob dependencies use
explicit tree entries. JSON object IDs alone never establish retention. Staged
candidates are invisible. Publication errors resolve through selected receipts
where possible and otherwise remain unknown; they are not automatically treated
as CAS conflicts.

Native V1 records remain readable and unchanged. New anchor versions distinguish
native and Git evidence. Metadata and code publications are separate
transactions, not one atomic snapshot. Ordinary code undo does not rewind
collaboration state. Device paths, credentials, access grants and active
execution journals are not portable metadata. Source actor identities remain
provenance after conversion.

## Delivery gates

ReviewStore shared-engine extraction preserves native root bytes and all native
cross-object audits. A reusable catalog or reader alone does not qualify local
review publication, portable artifact validation or review CLI support. Shared
command projection MUST retain all native catalog, relation, comment ownership
and linear/merged event reconstruction checks. External dependency verification
and publication are qualified separately by each provider.

Local ReviewStore publication uses canonical repository-bound records and a
selected record-to-Git-blob inventory. Root reads audit selected retention and
the complete shared review closure; staged objects remain unavailable through
pinned reads. Command receipts precede entity preconditions, ref races reapply
typed intent to the selected root, and review updates preserve other domains.
Repository-wide threads can initialize metadata on first write. Until portable
code and agent anchor validation/retention is qualified, those targets MUST fail
closed rather than substitute repository or display-only identities.

The server-free custom CLI uses the same local typed provider for Thread and
rich reaction commands, including original custom raster bytes and retained
previews. Explicit request IDs, exact observed reaction sets and expected emoji
versions are passed unchanged. Read-only CLI commands leave absent metadata and
actor state absent. Cross-process pages bind the named current metadata commit;
changed state returns stale and requires explicit refresh. Native RPC support is
qualified independently rather than silently opening a local Git profile.

CLI mutation input admission is shared across providers without changing local
intent or receipt encodings. Native --cursor and local --after/--at-metadata
continuations are explicitly disjoint; profile-mismatched selectors fail closed.

Local Thread/Reaction commands and results use the shared jj-collab typed domain
variants. Existing local names remain public aliases and preserve exact JSON
tags, field order and receipt framing. Filesystem admission, actor derivation,
ref publication and portable evidence retention remain local provider policy.

Local WorkStore pagination reuses the native record and four-MiB page limits.
Continuations bind an immutable selected metadata commit, filters, page size and
offset. A continuation can only name selected history, never a staged candidate;
it remains usable across CLI processes while that bounded history is retained.
Actor identities are device state under the shared JJ repository, so physical
workspaces and the local UI use the same actor. They carry no access grants and
are excluded from portable transfer.

The local AgentStore uses the existing canonical repository-bound immutable
record envelope and one shared normalization, transcript and catalog engine. The
selected version-2 domain descriptor binds the complete record-to-Git-blob
inventory; reads audit retained membership and expose only the pinned root
closure. A sanitized capture request binds its original batch and profile before
reduction, so receipt replay precedes overlap checks and generated object
identities do not alter intent. A ref race retries against the selected root;
source overlap still fails stale. Publishing AgentStore preserves WorkStore and
other domains. Native V1 code associations require native evidence and are
rejected by this provider unless a native evidence provider is available.
Portable association/checkpoint commands bind original records, exact capsule
bytes and expected immutable selections. The provider validates source identity,
operation/profile and commit membership, retains the complete physical Git
closure and selects the evidence inventory alongside the AgentStore root.
Missing, mismatched or unselected capsules fail closed. Corrections retain prior
versions and require exact stale preconditions; receipt replay precedes those
checks.

CLI provenance publication synchronizes its complete typed request in private
device state before companion ref CAS. The journal binds repository and actor;
retry cannot recapture evidence or substitute another record under the same
request identity. Explicit-operation evidence inspection stages only immutable
objects and does not select metadata or alter JJ operation heads.

CLI hook ingestion retains the existing sanitizer-before-durability boundary.
Its shared private spool persists the complete local typed request before a
companion ref publication, checks the receipt's repository, actor, request,
intent and batch, and removes an entry only after a matching committed result.
Unknown outcomes retain that exact request across process restart and block
later source batches. Native prepared deltas and local prepared requests cannot
be delivered through each other's provider. Local session continuations bind
selected metadata history and stay usable across CLI processes.

Local recovery uses the same per-spool drain lease as native recovery and takes
the capture mutation lock only for bounded local journal I/O. Companion
publication never holds the enqueue lock. Cancellation and unknown outcomes
release the drain lease without discarding the exact prepared local request.

Portable evidence uses an explicit source profile and SHA-256 capsule identity.
The Git profile records the complete selected operation and view, including
predecessor maps, and the complete backend commit metadata needed by their
bounded ancestry/evolution closure. Operations and views retain their exact
upstream content identities. Git commit/tree/blob identities remain SHA-1; the
all-zero upstream root sentinel is never treated as a physical Git object. This
archives source context without installing or replaying an old operation graph.
Native V1 envelopes and codecs remain unchanged.

Portable agent provenance models retain typed operation capsules and commit
evidence pairs. Code changed/no-change/not-observed is validated independently
of capture completeness and execution outcome. Shared non-code policy does not
grant a provider permission to accept missing source capsules: local persistence
must qualify selected evidence and its retained closure separately.

Portable V2 review targets name actual retained sessions, tool invocations and
input/output payloads rather than inferring execution attempts from tool-call
IDs. The shared model validates exact session membership, stable identities,
content selection and UTF-8 byte digests. Local providers must additionally
prove committed record membership and complete retained Git closures before
enabling their publication. A model or successful structural check does not
enable the browser capability.

Local portable agent review inspection pins an explicit committed companion
selection and admits only exact AgentStore records in its audited root closure.
It validates session/tool ownership and stored input/output bytes through the
shared model; staged records and records first selected after the requested pin
remain unavailable. An optional agent-root context must match that selection,
and native publication counters are unsupported. Inspection never initializes
metadata or a device actor and rechecks the admitted history before returning.
This is source validation, not a selected review or a write authorization.

## Independent conversion profile

Destination preparation reconstructs supported historical domain selections with
explicit reference maps. Native staging freezes origin execution through a new
WorkStore home; final publication copies its verified closure manifest last.
Local staging selects typed descriptors together, retains the exact archive as a
reachable companion blob and exports only through a no-replace folder rename. An
installation journal retains original archive bytes and reports independently of
the source. Status polling never allocates a new staging attempt. An explicit
retry of interrupted preparation may start a fresh private staging attempt under
the same destination identity; completed preparation and final publication reuse
the retained digest-selected report. Mapping reports include transformed records
and selected catalog roots; rebuilt internal catalog pages have no one-to-one
identity correspondence. These artifacts do not grant execution or access.

Conversion pins a committed source operation and companion or manifest selection
without snapshotting working files or reconciling heads. The source archive is
read-only and bounded to 100,000 objects, 16 MiB and dependency depth 512. The
integration boundary translates code identities explicitly, preserving parents,
predecessors, complete selected view references and the operation's optional
predecessor map. A fresh destination operation has only the built-in root as its
parent; the source operation graph remains provenance, never a replay recipe.
File identities are verified independently of envelope checksums. Git SHA-1
objects are verified against their raw bytes before translation. Source settings
and hooks do not execute. Signing, code conflicts and non-placeholder copy IDs
require separate qualified profiles and fail preflight. Collaboration conversion
must audit every historical domain selection; unsupported exact evidence may
prevent conversion but may never be silently omitted. Source grants,
credentials, settings, device registrations and active execution journals are
not destination authority. Existing project repository links keep their original
identities.

## M15 additive collaboration publication

Threads and Reactions use independently selected canonical roots and immutable
complete-closure inventories. Native manifest format 5 adds optional roots and
state versions; local companion version 2 extends the owned ref envelope on
first feature use. Earlier formats remain byte-identical. Publication providers
retain original request receipts and expected-state checks; staging is
invisible. Cold recovery and copy audit all current and historical selected
roots, including raster assets and external AgentStore/ReviewStore/code
dependencies. Reducer 3 qualification precedes replicated collaboration
publication; unsupported origins fail closed. No replay executes agents or
fetches image bytes.

The local Thread and Reaction descriptors each select their own canonical root
and sorted complete content-ID-to-Git-blob inventory. Reads verify retained tree
membership, canonical identity, exact graph closure and external source
closures; they cannot read staged blobs or extra inventory entries. Agent and
review references retain the existing repository-bound bytes in separate
inventories. Portable code links retain exact qualified capsules; native code
IDs and stronger unqualified attribution fail closed in this profile.

Local typed commands derive the actor from device provenance, check selected
receipts before target/entity preconditions, and retry an expected-old-ref race
against all newly selected roots. Set/Clear/ResolveConflict and custom library
commands use the shared pure projector. Source/preview blobs remain reachable
after image replacement, retirement, process reopen and ordinary Git GC.
Existing sessions stay unlinked until an explicit link command. Reaction query
pages resolve current target visibility before returning actor slots, accept at
most 256 rows and four MiB, and require the captured metadata commit for a
continuation. Raw reaction records are not exposed by the local asset reader.
Capture-plus-binding publication and cold full-process CLI/UI acceptance remain
separate pending gates.

## Local browser delivery slice

M13.4 is delivered in independently verified stages. Folder registration,
filesystem-only serving, code browsing, WorkStore editing and qualified
AgentStore reads reuse the M13.1/M13.2 foundation and recorded M13.3 provider
proofs. They do not advertise unqualified ReviewStore anchors or code mutations.
Indexed search, recoverable code commands and the remaining review gates remain
explicitly pending; this slice cannot complete M13.4 or M13.

Folder inspection and all GETs are non-publishing. Explicit Add may initialize
companion identity using the existing agent initialization command; it never
installs capture hooks, creates a project or snapshots checkout files. A durable
installation-owned request precedes initialization and binds canonical folder,
shared JJ metadata path and original intent. Replay recovers the selected
receipt before making the folder discoverable. Folder removal affects only
device discovery. Each read revalidates identity and binding generation.

Admission persists the proposed repository identity before first companion
publication. Initialization retries must use that identity and fail closed when
another identity appears. All journal records, request IDs, generations and
recorded results are validated on restart. Explicit reconnect accepts a
supported folder with the original identity, preserves project links, and
increments the binding generation. A different ready copy is rejected; reconnect
never changes repository contents or initializes replacement metadata.

Local code APIs are separate from native DTOs and preserve Git SHA-1 IDs and
explicit JJ operations. Collaboration pins a separate committed metadata
selection; staged commits and unrelated cursor histories are unavailable. Local
providers expose only bounded owned queries and existing collaboration commands.
Installation-level registration is LocalTrusted administration, and local
folders are never exposed through authenticated shared deployments.

Mixed and filesystem-only startup use the same device registry and browser. The
filesystem mode requires no object-store runtime or native RPC. Local freshness
notifications announce changed operation heads or companion refs; the browser
automatically recaptures active selections without moving explicit historical
code pins. An unavailable folder, changed identity or unsupported capability is
distinguished from denied access.

Format-2 server configuration selects filesystem storage explicitly; native
storage remains the default. Filesystem startup requires literal-loopback
LocalTrusted administration and rejects native backup, search and replication
configuration. Bootstrap and discovery identify the available authority.
Installation management and operation-pinned code APIs use the separate
`/v1/local` namespace, with process-bound cursors that bind repository, binding
generation, operation and query. Native URLs and native identity widths retain
their existing contracts.

The browsing stage provides owned Git-profile graph, content, references,
operation-difference and conflict descriptors. A local binding generation and
explicit operation replace native manifest positions in its code snapshot; there
is no fabricated native epoch, WAL position or publication sequence.
Content-filter revsets remain disabled until their bounded resource proofs are
qualified. File text is bounded; binary/oversized content reports its status.

### Pinned local WorkStore transport

Local repository-card ReviewStore activity uses an explicit committed companion
pin and current folder admission, then reads only selected thread/event facts
for a bounded first catalog window. Full descriptor/retained-object closure
admission remains mandatory before deriving the count and maximum timestamp.
Activity responses do not hydrate comment or anchor presentation and mark the
count incomplete whenever the selected window has more catalog entries.

Local browser WorkStore pages require an explicit committed companion metadata
selection, independently from the code operation. Initial pages and resumed
queries validate that selection against bounded current committed history and
reject staged or unrelated commits. Filtered summaries use the same complete
root projection, ordering, counts and bounds as native WorkStore. Browser
continuations bind repository, binding generation, metadata selection and exact
query; changed filters or another repository fail closed.

Local task activity pages use the same complete-root body-free
repository/project groups as native WorkStore. Their explicit companion commit
is admitted through current committed history, with the existing folder binding
checks and signed query-specific continuations. Page work copies only selected
aggregate rows. Work browse/activity/detail facades share a process-local,
data-only root projection after full companion admission and a fresh admitted
Work-blob read. The key includes repository, Work object and SHA-256 of its
bytes; metadata commits, versions and binding checks remain request-bound.
Missing objects, tighter source limits, unrelated/staged selections or replaced
identities MUST fail before cached data is returned. No identity-only
observation can substitute for a domain Snapshot.

Local Work projection retention is bounded to 32 roots, 256 MiB and five minutes
of idle time, with eight exact-query key sets per root. Construction is
serialized outside the root-cache map lock and reserves conservative
decoding/projection space before allocation. A 512-MiB process derivation
allowance accounts both construction and resident lifetimes; eviction releases a
resident charge only after its last reader exits. Each query-key set has its own
live charge, reserved before filtering/allocation and retained until its last
reader exits. Root retention includes the allowance for eight query slots;
evicted key sets still held by readers remain under the process live allowance.
Oversized retention may return the validated result request-locally under the
same live allowance; pressure may return Busy while active readers occupy it.
Ordinary WorkStore capacities, companion admission, formats and publication
semantics remain unchanged. Domain/retained-closure admission itself is still
required on every request and is separate from this projection reuse.

Local browser edits and status use the existing CLI device actor and original
typed WorkStore request. Receipt replay precedes stale entity checks. Transport
timeouts after dispatch retain the exact request as an unknown outcome; removal
or replacement of a folder binding cannot grant access to a retained page.

Admitted browser collaboration facades bind the original repository identity.
Every write checks that identity before device actor initialization and on each
publication retry; a replaced companion root is stale rather than another home
to which the original command may be applied.

### Local AgentStore browser selection

Recorded local agent reads require an explicit committed companion metadata
selection. They reuse audited AgentStore closure readers and shared sanitized
activity/timing/transcript presentation. Session and transcript identities
remain stable and immutable respectively. The shared timing projection may
recover qualified Codex JSONL RFC 3339 timestamps from exact matched sanitized
evidence when the observation timestamp field is absent. It preserves the
selected companion pin, including after later capture. Tool durations use only
ordered exact selected call/result or lifecycle endpoints, remain absent for
incomplete or ambiguous evidence and retain recorded outcome state. This
read-only projection neither rewrites recorded evidence nor requires reimport.
Portable code associations retain their exact source repository, Git SHA-1
commits, operations and evidence capsules; source identity is never substituted
with the metadata home. Browser relation queries are bounded projections of
selected associations and report continuation when more qualified records exist.
Reads cannot initialize metadata or record agents.

Companion-pinned AgentStore message activity and transcript pages expose
optional occurrence milliseconds from their exact selected evidence using the
shared qualified timestamp projection. Historical pins retain original message
times after later capture; reads do not publish or infer times from ingestion.

Local freshness streams revalidate device bindings and perform bounded checks of
operation heads and the selected companion ref. They announce current selections
without reconciling heads or changing working files. The browser compares
reconnect announcements against its retained selections and automatically
reloads new committed data, including changes missed while disconnected.

The browser selects transports by discovered profile and availability. Folder
controls persist the exact pending Add request in device browser storage before
dispatch. Reload checks its outcome; retry reuses the same intent. Removal and
reconnect retain repository and project identities. Browser collaboration roots
and current-head views refresh automatically; explicit historical code
selections remain pinned.

Local browser read transports reuse the existing bounded busy-retry policy for
shared read-worker admission. A retry retains the exact operation, companion
selection and query, including its continuation; it never captures a newer
snapshot. Only read operations retry automatically. Registration and domain
commands retain their explicit receipt and unknown-outcome handling.

### Physical working-file Save

Explicit Working copy editing reads the registered physical folder independently
from the displayed operation. Its selection binds repository, binding
generation, physical workspace identity, relative path and a fingerprint of file
identity, mode, timestamps and exact bytes. Existing regular UTF-8 files up to
256 KiB are qualified; traversal, metadata components, symlink traversal,
hard-linked files, special files and unsupported content fail closed. Save
revalidates the selection immediately before atomic, mode-preserving
replacement. It never snapshots files, publishes JJ heads or changes the
companion ref. Snapshot remains a separate explicit action. File drafts survive
stale selections and uncertain responses; readback can confirm the current file
matches the draft, never a JJ receipt. Concurrent browser saves serialize.
Arbitrary external filesystem writers do not participate in a filesystem CAS;
final fingerprint checking detects prior changes but cannot guarantee exclusion
of a writer racing the atomic rename.

## Bounded local code reads

Operation/view-only requests MUST prove the selected operation is retained and
stop ancestry discovery once that proof is available. Query information,
operation detail and bookmark-only pages MUST NOT load a commit graph, build a
JJ index, or traverse historical trees. Historical selections remain bound to
current retained operation ancestry; raw Git object existence is insufficient
for membership.

Bookmark pages without a search predicate MUST select their ordered window
before reading target commits. Hydration reads only targets referenced by the
selected view, remains within the request byte/work/deadline limits, and reports
exact conflict terms and workspace links. Description search retains complete
matching semantics; bounded preparation for wider queries is a separate stage.
Existing local publication, identity and persisted formats remain unchanged.

Local commit-index construction MAY use the shared disk-backed JJ format-6
builder through profile-specific admitted readers. Starting from a retained
operation proof, traversal follows only operation parents, referenced commit
roots and commit parents; raw Git object existence grants no new roots. Each
operation, view and commit read rechecks the registered binding and per-object
byte/shape limits. Preparation does not load trees, decode the repository's
derived index, reconcile heads or publish native/companion state.

The trusted caller reserves a private disposable output allowance before
invoking construction. Scratch and streamed output share that allowance. One
shared preparation permit remains held through actual cancellation/worker exit.
Construction has separate cumulative work, bytes, metadata and deadline limits;
it never increases ordinary interactive limits. Failed output is deleted and a
successful handle owns its disposable files. Library handles serve prepared log,
commit detail and evolution pages; the service owns retained generations and
task delivery. Large-scale qualification remains a separate gate.

Preparation MUST NOT invoke GitBackend's implicit extra-metadata import or
stacked-table reconciliation. It reads compact commit fields from Git and
performs bounded read-only seeks in captured, checksum-verified JJ 0.45.1 extra
metadata segments. Preserve imported and explicit change IDs, shallow roots and
JJ's commit timestamp ordering. A missing extra record uses upstream's header or
synthetic change ID without importing it. Segment disagreement, invalid framing
or identity mismatch fails explicitly; no tree bytes are needed for indexing.

A prepared local log page MUST bind the exact repository, registration
generation and operation from construction, and create fresh authorized source
readers for each request. It may reuse a verified immutable resident index;
membership comes from that operation's constructed closure, never arbitrary Git
object existence. Returned commit records preserve JJ signatures, conflict tree
terms/labels, legacy predecessors and extra change IDs through a read-only
decoder. No extra-metadata import, source index repair or publication is
allowed. Interactive work/byte/row/deadline limits remain unchanged. Syntax
admission must not multiply query length by total repository commit count.
Retained generation and index-memory admission, task delivery and deep-page
qualification remain explicit independent gates. Resident admission shares a
process-wide 1 GiB allocation allowance with native graph indexes. It
conservatively charges twice the index segment bytes plus retained
metadata/shallow-root overhead before decoding. Charges live until the last
handle is released. Verify the complete bounded segment and fixed operation link
before decoding; an unexpected upstream rebuild must fail through a view-denying
capability. Prepared pages consult the memory copy and must survive damage or
removal of their disposable index files. Source extra segments remain read-only
retained handles checked before and after seeks for size, identity and timestamp
changes. Coarse or unsupported timestamp proofs require bounded full checksum
checks; changed segments fail explicitly even if mtime is restored. No earlier
caller's credentials are retained.

## Rich history query delivery

The registered-folder `query_info` request MUST share the existing local
operation pin and worker admission. Its catalog excludes unqualified content and
cross-operation predicates. Standard JJ 0.45.1 aliases MUST evaluate against
server defaults with explicit email/workspace/time context, regardless of
user/repository aliases. The additive `operations_filtered` graph variant uses
the same bounded metadata grammar as native repositories and preserves sparse
pagination, actual operation parents and exact continuation bindings. Reads MUST
preserve operation-head files, physical dirty files and companion selections.
Custom aliases and local content/cross-operation predicate qualification remain
deferred.

Registered-folder query metadata MAY default author email from host JJ
configuration (JJ_EMAIL and normal JJ user paths), then the registered
repository's JJ configuration, then Git configuration. JJ 0.45 secure repository
config is read only when its metadata binds the registered repository path;
legacy config remains a read-only fallback. Reads MUST NOT migrate config,
snapshot dirty files or alter heads. Only bounded email is returned; custom
aliases remain isolated from query evaluation. Missing/malformed email leaves
explicit session input available.
